## 1. 검토해서 **기각**한 것

### 1.1 위상 정렬 (주파수 간 Δ²φ)

**가설**: transient 는 전 대역 위상이 정렬되고, 평탄 steady 는 위상이 무작위다.
진폭만 보면 둘이 같은 칸에 놓이는데 위상 축을 더하면 분리된다.

**측정** — 복소 곱 $B[k]=X[k+1]X[k-1]\overline{X[k]}^2$ 로 구현(wrapping 자동 처리, 진폭 가중 내장).
합성 신호로 도구 검증 후 실데이터 적용.

| 특질 | steady | transient | AUROC |
|---|---|---|---|
| 위상 정렬 coh | 0.595 | 0.787 | **0.698** |
| [기준선] 이동창 std | 0.039 | 0.064 | **0.854** |

| 진폭 5분위 | AUROC (coh) |
|---|---|
| Q4 | **0.462** (우연 이하) |
| Q5 | 0.585 |

**기각 사유 — 전제 3개가 모두 깨진다**

| 전제 | 실측 |
|---|---|
| 평탄 steady = 무작위 위상 | **lag-1 자기상관 0.922.** 합성 AR(1) ρ=0.85 에서 이미 coh 0.513 (무작위면 0.168) |
| transient = 광대역 | **반대다.** 스펙트럼 엔트로피 steady 0.589 > transient 0.497, 최저 5 bin 파워 비중 0.563 < **0.799**. 여기 transient 는 step 이 아니라 7–11 s 지수 정착이라 저주파에 몰린다 |
| 주기형 steady 는 배음에서만 정렬 | **순수 사인 → coh 1.000.** 협대역이면 위상이 매끄러워 transient 와 똑같이 "정렬" 로 판정된다 |

추가로 **노리던 실패 모드가 이 데이터에 없다** — std 하위 20% steady 의 성질이 전체 steady 와 같다
(엔트로피 0.588 vs 0.589, coh 0.854 vs 0.860). "평탄형 steady" 가 별도 모드로 존재하지 않는다.

> 같은 틀 위에 있는 **시간 비가역성(방향성)** 도 함께 보류했다. 다만 이 재료는
> 뒤에 §2.2 에서 **다른 방식으로 되살아난다.**

### 1.2 추세-요동 독립성 위반 (C3)

**가설**: CoST 는 trend 와 seasonal 을 독립으로 가정하는데, transient 에서는 처짐 깊이에 따라
빠른 요동도 함께 변해 그 가정이 깨진다. 그 의존성을 transient 점수로 쓴다.

**측정** — 차수 1 기준으로 느린/빠른 성분을 가르고 $|e_{\rm slow}|$ 와 ${\rm env}(e_{\rm fast})$ 의
창 내 상관을 계산. **합성 대조군으로 양자화 인공물이 없음을 먼저 확인**(독립 생성 시 진폭을

| 특질 | steady | transient | AUROC |
|---|---|---|---|
| `corr` (의존성) | 0.025 | 0.112 | **0.586** |
| **`fast_amp`** | 0.0391 | **0.0379** | **0.526** |
| [기준선] `movstd` | — | — | 0.789 |

**기각 사유** — `fast_amp` 가 0.526 이다. **빠른 요동의 크기가 상태와 무관**하다.
변하는 것은 느린 성분뿐이므로(`slow_amp` 0.021 → 0.056) 전제 A3-3 이 성립하지 않는다.

> 고속 전이 **+0.053**, 진폭 Q5 통제 후 **0.791**. §13.10 P4 로 남겼다.

### 1.3 표현 탈상관 (VICReg/Barlow 류) — 내가 제안했다가 스스로 기각

## 2. 구현한 것

### 2.0 용어 — 회전 차수(order)란 무엇인가

아래 전부에서 쓰는 개념이라 먼저 정의한다. 회전기계 진동 분석의 표준 용어다.

**정의**: **차수(order) = 회전 주파수의 배수로 센 주파수.** 차수 1 = 1회전당 1회,
차수 2 = 1회전당 2회. 주파수를 Hz 가 아니라 "회전 몇 번당 몇 주기" 로 세는 것이다.

**왜 이 데이터에 필요한가** — 롤러 둘레 $C = 783.5$ mm (205 run 평균, 지름 249.4 mm)이고
웹 속도 $V$ 에서 롤러 회전 주파수는

$$f_{\rm rot} = \frac{V}{C}\ \text{Hz}$$

| $V$ (mm/s) | $f_{\rm rot}$ (Hz) | 1회전 주기 | 1회전 샘플 수 | 창 144 에서의 bin |
|---|---|---|---|---|
| 50 | 0.0638 | 15.7 s | **143.8** | **1** |
| 100 | 0.1276 | 7.8 s | 71.9 | **2** |
| 200 | 0.2553 | 3.9 s | **35.9** | **4** |

롤러 편심·베어링 결함·접합부처럼 **하나의 물리적 원인이 만드는 교란은 "1회전당 1회" 로 고정**인데,
Hz 로 보면 속도에 따라 4배 움직인다. 차수로 보면 속도와 무관하게 **항상 차수 1** 이다.

**CoST 에서 이것이 문제가 되는 지점** — `BandedFourierLayer` 는 **bin 마다 독립된 복소 가중치**를
학습한다 (원본 `models/encoder.py`):

```python
self.weight = nn.Parameter(torch.empty((num_freqs, in_channels, out_channels), dtype=torch.cfloat))
...
output = torch.einsum('bti,tio->bto', input[:, start:end], self.weight)   # t = 주파수 bin 인덱스
```

즉 모델에게 **"bin 번호" 가 의미를 갖는다.** 저속에서 bin 1 의 가중치가 배운 "롤러 교란" 이
고속에서는 bin 1 에 없다. 가중치가 엉뚱한 성분에 걸린다.

**무엇을 변형하는가** — FFT **직전에 시간축을 비틀어** bin 을 차수로 만든다.

```
1. trunk 출력 (B, T, 320)
2. 속도 s 별로:  w = ceil(N_rot x 1회전샘플수(s))      <- 그 속도에서 정확히 N_rot 회전분
                seg = input[속도==s, T-w:]              <- **창의 뒤쪽** (미래를 보지 않는다)
3. seg 를 선형보간으로 길이 L_ORD 로 재표본화          <- 모든 속도가 같은 길이
4. 원본 연산 그대로: rfft -> bin별 복소 가중 -> irfft
```

$N_{\rm rot}=1$ 에서 2~3 단계:

| $V$ | 뒤쪽에서 자르는 길이 | → 재표본화 후 |
|---|---|---|
| 50 | 144 (1회전) | 36 (4배 다운샘플) |
| 100 | 72 (1회전) | 36 (2배) |
| 200 | 36 (1회전) | 36 (그대로) |

재표본화 뒤에는 모든 속도의 구간이 "$N_{\rm rot}$ 회전 = $L_{\rm ORD}$ 샘플" 이므로
**bin $k$ = 차수 $k/N_{\rm rot}$** 가 되고 속도와 무관해진다.

**차수 해상도 = bin 간격 = $1/N_{\rm rot}$ 차수.**

| $N_{\rm rot}$ | 창 | $L_{\rm ORD}$ | 해상도 | 분해 가능한 것 |
|---|---|---|---|---|
| 1 | 144 | 36 | 1.00 차수/bin | 정수 차수만 |
| 2 | 288 | 72 | 0.50 차수/bin | 반차수까지 |

**설계에서 중요한 네 가지**

| | |
|---|---|
| $L_{\rm ORD}$ 를 **가장 빠른 속도** 기준으로 잡는다 | 더 크게 잡으면 고속 구간을 업샘플하게 되고, "윗 bin 이 보간으로 채워졌다" 는 사실 자체가 속도 단서가 되어 모델이 우회할 수 있다 (사전진단에서 확인) |
| **창의 뒤쪽**을 쓴다 | 미래 시점을 보지 않는다 — baseline 의 `casual=True` 와 같은 규약 |
| **되돌리지 않는다** | 최종 표현이 `season[:, -1]` 만 쓰고, 차수영역의 마지막 샘플 = 원 시간축의 마지막 샘플이다. 손실의 amp/phase 항도 차수영역에서 계산된다 |
| 출력 길이가 달라진다 | seasonal 은 $(B, L_{\rm ORD}, 160)$, trend 는 $(B, T, 160)$. 둘 다 `[:, -1]` 만 쓰이므로 concat 에 문제 없다 |

**$V$ 는 창 길이 결정에만 쓰고 표현의 특징으로 넣지 않는다** (§5 의 공정성 서술 참조).

#### Hz sfd vs order sfd — 같은 층, 다른 축

`sfd` 는 CoST 의 용어다 — **S**easonal **F**eature **D**isentangler, 즉 seasonal 분기 모듈
(짝은 `tfd` = Trend Feature Disentangler). `sfd` 가 **FFT 를 하는 층**이고, 아이디어 01 이
바꾼 것은 **그 FFT 를 어느 축에서 하느냐** 다. 연산 자체는 동일하다.

| | **Hz sfd** (원본) | **order sfd** (아이디어 01) |
|---|---|---|
| 클래스 | `BandedFourierLayer` | `OrderBandedFourierLayer` (위의 **서브클래스**) |
| FFT 입력 | trunk 출력 **그대로**, 창 144 샘플 (시간축) | 뒤쪽 $N_{\rm rot}$ 회전분을 $L_{\rm ORD}$ 로 재표본화 (각도축) |
| 연산 | `rfft` → bin별 복소 가중 → `irfft` | **동일** (`super().forward(seg)` 로 원본 호출) |
| **bin 의 의미** | $k/(144\,\Delta t)$ **Hz** — 0.0637 Hz 간격 | **차수 $k/N_{\rm rot}$** — 1회전당 주기 수 |
| bin 개수 | $144/2+1 =$ **73** | $36/2+1 =$ **19** ($N_{\rm rot}=1$) |
| 가중치 | (73, 320, 160) complex = **3.75M** | (19, 320, 160) complex = **0.98M** |
| **출력 길이** | $(B, \mathbf{144}, 160)$ | $(B, \mathbf{36}, 160)$ |
| 속도가 바뀌면 — 롤러 교란 | bin 1(V=50) → bin 4(V=200) **이동** ❌ | **항상 차수 1** ✓ |
| 속도가 바뀌면 — transient | Hz 가 거의 고정이라 **제자리** ✓ | bin 사이로 **이동** ❌ |

**마지막 두 줄이 핵심이다 — 두 축 각각이 한 성분을 고정하고 다른 성분을 놓친다.**

| 성분 | 고정된 축 | 측정 근거 |
|---|---|---|
| 롤러 교란 (**방해물**) | **각도** | $f_{\rm rot}=V/783.5$ 가 실측 피크와 0.006 Hz 이내 (§2.1) |
| transient 정착 (**표적**) | **시간** | 지속시간 9.4~17.8 s. 각도 고정 가설(∝1/V)은 V=200 에서 예측 4.45 s vs 실측 13.67 s 로 **기각** |

transient 지속시간 실측 (`Trigger 4` 라벨의 연속 non-steady 구간, run 평균):

| V | 50 | 75 | 100 | 125 | 150 | 175 | 200 |
|---|---|---|---|---|---|---|---|
| 최장구간 (s) | 17.78 | 14.31 | 11.60 | 9.40 | 9.45 | 10.04 | **13.67** |
| 각도 고정 예측 (s) | 17.78 | 11.86 | 8.89 | 7.11 | 5.93 | 5.08 | **4.45** |

U자형이고 시간 고정(일정)에 훨씬 가깝다. 제어 루프 정착 시간이 결정하는 양이라 당연하다.

> **그래서 차수의 동기를 "속도 불변성" 으로 서술하면 안 된다.** 속도 불변이면 전 속도에 고르게
> 들어야 하는데, 실제로는 **V=125 에 몰리고 V=200 은 손해**다 (§2.1 의 속도별 분해).
> 측정에 맞는 서술은 "차수 재색인이 seasonal 분기의 변별력을 올리며 baseline 이 약한 속도에서
> 가장 크게 듣는다" 이고, 고속 손해의 후보 설명은 아래 "덮는 비율" 이다.

**고속 손해의 후보 설명** — order window 의 시간 범위가 속도에 반비례한다 ($N_{\rm rot}=1$):

| V | order window | 시간 범위 | transient | **덮는 비율** | `order` F1 차이 |
|---|---|---|---|---|---|
| 50 | 144 | 15.7 s | 17.8 s | 88% | +0.0114 |
| 100 | 72 | 7.9 s | 11.6 s | 68% | +0.0178 |
| 125 | 58 | 6.3 s | 9.4 s | 67% | **+0.0345** |
| **200** | **36** | **3.9 s** | 13.7 s | **29%** | **−0.0076** |

유일하게 손해 나는 V=200 이 덮는 비율도 유일하게 30% 미만이다. 다만 V=50(88%)이 V=125(67%)보다
이득이 작으므로 **덮는 비율만으로 전 속도 패턴이 설명되지는 않는다** — 후보 설명이고 확정이 아니다.

#### 현재 order sfd 가 끼워진 방식 — 다른 방식을 제안하려면 이것을 알아야 한다

```python
class OrderCoSTEncoder(CoSTEncoder):
    def __init__(self, *a, l_ord, **kw):
        super().__init__(*a, **kw)                      # 원본이 Hz sfd(73 bin)를 만든다
        self.sfd = nn.ModuleList([OrderBandedFourierLayer(   # ← **통째로 교체** (Hz 판은 버려진다)
            self.output_dims, self.component_dims, 0, 1, length=l_ord)])

    def forward(self, x, **kw):
        self.sfd[0].speeds = ...x[:, :, 1]...           # 속도를 **속성으로 주입**
        return super().forward(x[:, :, :1].contiguous(), **kw)   # ch0 만 trunk 로
```

| | 현재 방식 |
|---|---|
| 끼우는 방법 | `self.sfd` 를 **통째로 새 `ModuleList` 로 교체.** 원본 Hz sfd 는 생성됐다가 버려진다 (= **완전 대체**, 병행이 아니다) |
| `ModuleList` 길이 | **1 유지** — 원본 `CoSTEncoder.forward` 가 `season = season[0]` 로 첫 모듈만 쓰기 때문 |
| 속도 전달 | `forward` 에서 `self.sfd[0].speeds` 에 **속성 대입**. 층은 자기 `forward` 에서 그 값을 읽는다 |
| 속도 채널 | `super().forward(x[:, :, :1])` 로 **잘라서** 넘긴다 → trunk·tfd 는 1채널만 본다 |
| `band`/`num_bands` | `(0, 1)` = **단일 전대역**. 원본도 같다 (대역 분할 기능이 설계상 있으나 쓰이지 않는다) |

**다른 방식을 설계할 때 제약이 되는 두 가지**

1. **원본 인코더가 `sfd[0]` 만 쓴다.**
   ```python
   season = []
   for mod in self.sfd:   # 순회는 하지만
       season.append(mod(x))
   season = season[0]     # ← 나머지를 버린다
   ```
   `sfd` 를 두 개로 두는 것만으로는 동작하지 않는다. **합성 코드를 직접 넣어야 한다.**
2. **출력 길이가 다르다** — Hz sfd 는 $(B,144,160)$, order sfd 는 $(B,36,160)$, trend 는 $(B,144,160)$.
   최종 표현은 `cat([trend[:,-1], season[:,-1]])` 로 **마지막 시점만** 쓰므로 길이가 달라도 되지만,
   **seasonal 손실은 `rfft(q_s, dim=1)` 로 시퀀스 축 전체를 쓴다.** 그래서 두 축을 합치려면
   길이를 맞추거나 손실 항을 둘로 나누는 결정이 필요하다.

### 2.1 아이디어 01 — 회전 차수 축 seasonal 분기

**한 줄**: CoST 의 seasonal 분기에서 **주파수 축을 Hz 대신 "회전 차수" 로 재색인**한다.

**문제** — `BandedFourierLayer` 는 bin 마다 독립 가중치를 학습하는데, 같은 롤러 회전 외란이
속도에 따라 **bin 1(V=50) → bin 4(V=200)** 로 옮겨 다닌다. 저속에서 배운 가중치가
고속에서 엉뚱한 성분에 걸린다.

**사전진단 — 전제가 강하게 성립**

| 속도 | 50 | 75 | 100 | 125 | 150 | 175 | 200 |
|---|---|---|---|---|---|---|---|
| $f_{\rm rot}$ 예측 ($V/783.5$) | .0638 | .0957 | .1276 | .1595 | .1914 | .2234 | .2553 |
| **실측 피크** | .0627 | .0986 | .1254 | .1613 | .1971 | .2240 | .2598 |
| 피크 두드러짐 (배) | 935 | 1046 | 1260 | 1329 | 623 | 933 | 777 |

차수 축으로 옮기면 피크 bin 이 **1~4 에서 2 하나로** 모인다 (shim 단위 검증 통과).

**구현** — `BandedFourierLayer` 를 서브클래스로 바꿔, trunk 출력의 뒤쪽 $N_{\rm rot}$ 회전분을

속도는 입력 2번째 채널로 실어 보내고 인코더 맨 앞에서 떼어낸다 (**trunk 는 e 1채널만 본다**).

### 2.2 아이디어 02 — 설정값 방향 게이트 (FiLM)

**한 줄**: "설정값에 다가가는 중인가" 를 시점마다 계산해 trend 표현을 FiLM 으로 조건화한다.

**되살아난 경위** — §1.1 에서 "방향성" 을 보류했는데, 그때 잰 것은 **샘플 단위** $\Delta(e^2)$ 였다
(transient 접근 비율 0.428, AUROC 0.743). 이 데이터는 자기상관 0.922 + 회전 외란이라
**샘플 단위 미분을 요동이 지배**한다. **1회전 길이로 평활**하니 신호가 드러났다.

$$r(t) = -e(t)\dot e(t),\qquad \bar s(t) = \tfrac1W\textstyle\sum_{\tau\in[t-W+1,t]}\mathbb 1[r_{\rm smooth}>0]$$

방향을 **부호가 아니라 설정값 접근/이탈**로 정의하므로 sag 회복(추세 +)과
overshoot 회복(추세 −)이 하나로 묶인다 (실측: 184 run 중 처짐 181 / overshoot 48).

**사전진단 — 지금까지 중 가장 강하다**

| 평활 길이 | steady $\bar s$ | transient | AUROC |
|---|---|---|---|
| 없음 | 0.502 | 0.428 | 0.743 |
| **$P(V)$ = 1회전** | **0.518** | **0.205** | **0.912** |
| [기준선] `movstd` | — | — | 0.789 |

| 진폭 5분위 | Q1 | Q3 | Q4 | **Q5** |
|---|---|---|---|---|
| AUROC | **0.965** | 0.884 | 0.862 | **0.931** |

**진폭 기준선을 넘고, 진폭을 통제해도 유지되는 첫 아이디어**다.
속도별로도 0.84~0.97 로 고르고, 속도 150(통계 기준선이 0.695 로 무너지는 조건)에서 **0.932** 다.

평활 길이 $P(V)$ 는 **유도값**이라 임의값이 늘지 않는다 — 아이디어 01 과 같은 둘레 상수에서 나온다.
창 내 **중심** 평활을 써야 한다 (인과 이동평균은 지연 $P/2$ 때문에 V=200 에서 0.912 → **0.599** 붕괴).

**A 실험 결과 — 효과 0**

| 방법 | 보존률 | **F1(ns)** | AUROC | AUPRC(ns) |
|---|---|---|---|---|
| baseline | .990 | **.913** | .978 | .853 |
| `CoST-W144-dirgate` | .990 | **.914** | .979 | .854 |
| 차이 | +.0001 | **+.0009** | +.0006 | +.0017 |

FiLM 은 영 초기화에서 출발했는데 `|weight|` 가 **0.00133** 에 머물렀고 fold 가 달라도 값이 같다
— **데이터에 반응한 것이 아니라 gradient noise 만 누적**된 것이다.

### 2.3 아이디어 03 — 설정값 방향 보조 손실 (**실행 완료 2026-10-29, baseline 초과**)

**한 줄**: 같은 $\bar s$ 를 **구조가 아니라 손실**에 넣는다.

$$\mathcal{L} = \mathcal{L}^{\rm MoCo}_{\rm trend} + \alpha\cdot\tfrac12\mathcal{L}_{\rm season}
+ \boldsymbol{\beta\cdot\lVert \mathbf w^\top\mathbf h_T - \bar s\rVert^2}$$

trend 표현 160차원에서 **선형 head 하나**로 $\bar s$ 를 예측하게 한다. 예측하려면 표현이
방향 정보를 담을 수밖에 없다. head 를 선형으로 최소화하는 것이 핵심 — MLP 면 head 가
혼자 일을 해버려 표현이 안 바뀐다.

**$\beta$ 는 크기를 재서 정했다**

| 항 | 실측 |
|---|---|
| $\mathcal{L}^{\rm MoCo}$ | 0.045 → **3.25** (MoCo 큐가 차면서 70배 증가) |
| $\mathcal{L}_{\rm aux}$ 초기값 | $\approx{\rm Var}(\bar s)=0.026$ |
| → 기존의 10% 로 두는 값 | **$\beta=12$** (기본값) |

$\beta=1$ 은 전체의 0.8% 라 아이디어 02 와 같은 결과가 난다. CLI 인자로 빼 민감도 확인이 쉽다.

**읽기 시점 2종 비교** (연구자 지시)

| 변형 | $\mathcal{L}_{\rm aux}$ |
|---|---|
| `saux-point` | MoCo 가 쓰는 무작위 시점 1개만 제약 |
| `saux-mean` | **시점별 오차를 전 시점에서 평균** (창 평균끼리 MSE 가 아니다 — 선형 head 에서는 그게 약한 제약이 된다) |

**학습됐는지 측정하는 장치** — 아이디어 02 의 `film_weight_absmean` 이 "안 썼다" 를 드러냈듯,
`aux_r2 = 1 - \mathcal{L}_{\rm aux}/{\rm Var}(\bar s)` 를 기록한다.
0 근처면 "표현이 안 담았다", 1 에 가까우면 "담았다" 가 확정된다 — **성능이 안 올라도 원인이 구분된다.**

**실행 결과 (2026-10-29, A 실험 5 fold × 5 seed, baseline 과 짝지은 Wilcoxon n=25)**

| 변형 | `aux_r2` | F1(ns) | AUPRC | AUROC | 보존률 |
|---|---|---|---|---|---|
| `saux-mean` | +0.091 | **+0.0047** 16/9 p=.017 | **+0.0081** p=.019 | **+0.0098** 23/2 p<.001 | −0.0013 4/21 p=.002 |
| `saux-point` | +0.057 | **+0.0043** 17/8 p=.030 | **+0.0076** p=.027 | **+0.0101** 24/1 p<.001 | −0.0014 4/21 p=.001 |

**가설은 지지됐다** — 같은 재료를 구조로 준 02 는 효과 0(p≥0.46)인데 손실로 요구한 03 은 유의하게
개선된다. "손실이 요구하지 않으면 학습이 안 쓴다" 는 명제가 음성·양성 쌍으로 확인됐다.

**그러나 효과가 작고, 그 이유도 측정됐다 — 표현이 보조 과제를 거의 못 푼다** (`aux_r2` 0.09).
압력을 키우면 발산한다: $\beta$=30 에서 10번째 iteration 에 $\mathcal{L}_{\rm aux}$ 1.8e4 → NaN,
인코더 파라미터 전부 NaN. 원인 둘 — ① 보조 손실이 정규화 전 trend 표현에 직접 붙어 표현 크기를
키우는 양의 되먹임이 생긴다 ② 학습 초반 $\mathcal{L}^{\rm MoCo}$ 0.045 대비 $\beta\mathcal{L}_{\rm aux}$ ≈ 1~3 이라
보조가 지배한다(§2.3 의 ⚠ 가 예고한 상황). **$\beta$ 민감도는 종결했다** — β=12 고정으로 보고한다
(`hyperparameters.md` §13.10 P2).

**P3 (보조 head 가 trend 160 대신 표현 320 전체를 읽는 변형) — 기각.** 25/25 전부 악화
(F1 −0.131, AUPRC −0.196, 보존률 −0.034). 그런데 `aux_r2` 는 **올랐다**(0.09→0.12).
보조 과제는 더 잘 풀렸는데 다운스트림이 무너졌다 — `03_*.md` §5 위험 1 이 실현된 것이고,
**seasonal 표현에 보조 압력을 주면 그 분기가 망가진다**는 뜻이다. 보조 항은 trend 에만 건다.

## 3. 두 개입의 비교 — P1(보조 손실) vs P5(이원 trunk)

실행을 마친 P1(아이디어 03)과 다음 후보 P5(이원 trunk)는 **문제를 보는 지점이 다르다.**
개입을 고르는 기준을 남기기 위해 가설과 이론적 개념을 나란히 적는다.

### 3.1 P1 — 아이디어 03: 설정값 방향 보조 손실

**가설**

| # | 주장 | 근거 |
|---|---|---|
| H1 | CoST 의 목적함수에는 **상태 구분 과제가 없다.** 대조 학습은 "같은 run 의 두 증강본을 가깝게" 만 요구한다 | $\mathcal{L} = \mathcal{L}^{\rm MoCo}_{\rm trend} + \alpha\cdot\frac12\mathcal{L}_{\rm season}$ 에 상태 항이 없다 |
| H2 | 상태 정보의 **재료는 충분히 강하다** | $\bar s$ 단독 AUROC **0.912** (진폭 기준선 0.789, 진폭 통제 후 0.86–0.97) |
| H3 | 그래서 **구조로 넣으면 학습이 버리고, 손실로 요구하면 표현이 담는다** | 아이디어 02 효과 0, FiLM $\lvert w\rvert$ 0.00133 |

> 핵심 명제: **"정보가 없어서가 아니라 쓸 이유를 못 줘서 안 쓴다."**

**이론적 개념** — **보조 과제를 통한 표현 유도** (auxiliary-task representation shaping).
자기지도 목적함수에 약한 지도 신호를 더해 표현 공간을 원하는 축으로 기울인다. 급소는
**head 를 선형으로 최소화**한 것 — MLP 면 head 가 혼자 일을 해버리므로 용량을 없애 압력을
표현으로 전가시킨다 (선형 프로브를 목적함수로 쓰는 것).

**정보론적 성격** — 정보를 **더하지 않는다.** $\bar s = f(e)$ 로 오차 신호만으로 계산되고
인코더의 입력이 바로 $e$ 다. 개입의 내용은 "무엇을 담을지 지시" 다.

### 3.2 P5 — 이원 trunk: 분기별 창 분리

**가설**

| # | 주장 | 근거 |
|---|---|---|
| H1 | CoST 는 표현을 **trend(시간 영역) + seasonal(주파수 영역)** 으로 분해하면서 **두 영역에 같은 창을 강제**한다 | 공유 trunk 하나 + `max_train_length=W` / `sliding_padding=W−1` 가 두 분기의 수용 영역을 동일하게 고정 |
| H2 | 두 영역이 요구하는 창 길이는 **반대**다 | 창 288 → trend 붕괴 (Prec(ns) 0.877→0.464, 진입 MAE 5.1→12.8 s) / 창 288 → 차수 해상도 1.00→**0.50** 차수/bin |
| H3 | 단일 창은 둘 중 하나를 **반드시 희생한다.** 분기별로 창을 분리하면 희생 없이 둘을 얻는다 | 창 손해 **−0.291**(trend 기인) vs 차수 효과 **+0.175**(seasonal 기인) |

> 핵심 명제: **"시간/주파수로 분해하는 모델이 두 영역에 같은 창을 쓰는 것은 분해의 의미를 깎는다."**

**이론적 개념** — **시간–주파수 해상도 상충의 분기별 분리** (branch-wise time–frequency
decoupling). 불확정성 원리상 한 창으로는 시간 국소화와 주파수 해상도를 동시에 올릴 수 없다.
다중해상도 분석(wavelet, multi-resolution STFT)이 쓰는 해법 — **영역마다 다른 창** — 을
CoST 의 두 분기에 적용한다.

구조적으로 가능한 이유: **CoST 의 두 손실 항이 이미 분기별로 갈라져 있다.** `L_MoCo` 는 trend 만,
`α·L_season` 은 seasonal 만 쓴다. 둘을 묶는 것은 trunk 하나뿐이므로 trunk 를 가르면
손실 수술이 필요 없다.

**정보론적 성격** — 정보를 **더하지 않는다.** 대신 **이미 작동하는 효과를 막고 있는 제약을
제거한다** — 차수 효과는 창 288 에서 이미 +0.175 로 관측됐다.

### 3.3 나란히 보기

| 축 | **P1 (아이디어 03)** | **P5 (이원 trunk)** |
|---|---|---|
| 무엇이 문제라고 보는가 | **목적함수** — 상태 구분을 요구하지 않는다 | **구조** — 두 영역에 한 창을 강제한다 |
| 개입 지점 | 손실 (항 하나 추가) | 아키텍처 (trunk 분리) |
| 이론적 개념 | 보조 과제 기반 표현 유도 | 시간–주파수 해상도의 분기별 분리 |
| 이득의 경로 | 표현이 담는 **내용**을 바꿔서 | 표현이 보는 **범위**를 분기별로 바꿔서 |
| 정보를 더하는가 | 아니다 ($\bar s = f(e)$) | 아니다 (제약 제거) |
| CoST 와의 관계 | 설계 **유지** | 핵심 가정(공유 trunk) **수정** |
| 선행 근거의 종류 | **재료가 강하다** (0.912) | **효과가 이미 관측됐다** (+0.175) |
| 상한을 정하는 것 | **표현의 흡수 능력** — 측정됨 (`aux_r2` 0.09, 그 이상 발산) | **창 손해의 trend 기인분** — 미측정 (P5 가 그 분해 실험) |
| 창 대조군 | 불필요 (창 144 동일) | **필요** — 파라미터 2배이므로 `CoST-dual-T144-S144` |
| 신규성 수준 | **적용** — 보조 손실은 일반 기법, $\bar s$ 가 도메인 특화 | **구조** — 분해형 표현학습의 설계 결함 지적 |
| 결과 | +0.0047 F1 (p=.017) — 유의하지만 작다 | 실행 중 (2026-10-29) |

### 3.4 둘을 가르는 규칙 — 지금까지 측정으로 확인된 가장 일반적인 패턴

**P1 은 모델이 계산할 수 있는 양을 다시 가르치는 개입**이다. $\bar s$ 는 $e$ 에서 나오고
인코더는 $e$ 를 입력으로 받는다. 그래서 흡수 한계에 부딪혔다 — 02 는 완전히 버려졌고(효과 0),
03 은 `aux_r2` 0.09 에서 멈췄고, 더 세게 요구하면 발산했다. **같은 패턴이 두 번 반복됐다.**

**P5 는 모델이 계산할 수 없는 것을 가능하게 하는 개입**이다. 차수 해상도 0.50 차수/bin 은
창 144 에서 **원리적으로 얻을 수 없다** — 학습으로 극복할 수 있는 것이 아니라 창 길이가 정하는
한계다. 아이디어 01 이 성공한 범주와 같다 (외부 정보 $V$ + 학습으로 못 얻는 구조 변경).

| 개입의 범주 | 해당 아이디어 | 결과 |
|---|---|---|
| $e$ 에서 유도한 양을 되먹임 | 02 게이트, 03 보조 손실, (P4 대역 비율) | 효과 0 / **+0.005** / 예측: 작음 |
| 모델이 원리적으로 못 얻는 것을 공급 | **01 차수 정규화**, **P5 이원 trunk** | **+0.0124** / 실행 중 |

> **P4(대역 에너지 비율)가 이 규칙으로 걸러진다.** `ratio = env(e_fast)/|e_slow|` 의 두 성분을
> §1.2 에서 이미 따로 쟀는데, 분자 `fast_amp` 는 0.0391→0.0379 로 **3% 밖에 안 변하고**(AUROC 0.526)
> 분모 `slow_amp` 는 0.021→0.056 으로 **167% 변한다.** 즉 `ratio ≈ 0.038/|e_slow|` 로
> **단일 진폭량의 단조함수**이고, AUROC 0.804 는 사실상 $1/|e_{\rm slow}|$ 의 값이다 —
> "두 대역이 함께 정보를 나른다" 는 전제가 성립하지 않는다. 게다가 $e$ 만으로 계산되므로 위 표의
> 첫 줄에 속한다. 0.912 짜리 재료($\bar s$)도 흡수되지 않았으니 0.804 가 흡수될 이유가 없다.
> 유일한 강점인 **고속 전이 +0.053** 도 아이디어 01 과 같은 속도 축이어서 겹칠 위험이 가장 크다.
> **우선순위를 P5 뒤로 내린다** (2026-10-29).

## 4. 차수 재색인은 전용·비학습 trunk 를 요구한다 (2026-10-29, A 실험)

> **주장**: CoST 는 trend·seasonal 분리기가 **하나의 trunk 를 공유**한다. seasonal 분기를
> **차수 축으로 옮기면 그 공유가 깨진다.** 같은 용량을 공유로 주면 이득이 없고(p=0.49),
> 두 분기에 나눠 주어야 이득이 생기며(p=0.0002), **seasonal 분기를 아예 학습시키지 않는 것이
> 가장 좋다**(+0.0171, p<0.0001). 단 **차수 없이는 분리 효과가 사라진다**(p=0.13) — 원인은
> 용량이 아니라 **축 불일치**다. 절의 전개는 §4.2→4.3(용량 배제) → §4.4(교차 압력) →
> §4.7(동결·차수없는분리로 범위 확정) 순이다.

### 4.1 CoST 가 공유하는 것 / 분리하는 것

원본 `CoSTEncoder` 는 `feature_extractor`(DilatedConvEncoder, depth 10)가 **하나뿐**이고
`tfd`·`sfd` 가 **그 출력을 똑같이 받는다**.

| CoST 가 분리하는 것 | CoST 가 **공유하는** 것 |
|---|---|
| 표현 — trend 160 + seasonal 160 | **trunk** (`input_fc` + `feature_extractor`) |
| 분리기 — `tfd`(시간 영역 conv) / `sfd`(주파수 영역 Fourier layer) | |
| 손실 — $\mathcal{L}^{\rm MoCo}$(trend 만) / $\alpha\mathcal{L}_{\rm season}$(seasonal 만), $\alpha=0.0005$ | |

공유 backbone 은 **설계의 핵심**이다. "같은 특질을 두 분리기가 다르게 읽어 disentangle 한다" 가
원 논문의 주장이고 그래서 TFD/SFD 를 *disentangler* 라 부른다. trunk 를 가르면 더 이상 하나의
표현을 분해하는 것이 아니라 **독립 인코더 두 개의 출력을 이어 붙이는 것**이 된다.

### 4.2 근거 — 2×2 격자 (학습량 전부 동등, `data_passes` 3.17)

| 변형 | trunk | 차수 | F1(ns) | AUPRC | AUROC | 보존률 | baseline 대비 F1 |
|---|---|---|---|---|---|---|---|
| `CoST-W144-noscaleshift` | 공유 64 | — | .9132 | .8525 | .9782 | .9903 | 기준 |
| `CoST-W144-noscaleshift-h116` | 공유 **116** | — | .9122 | .8506 | .9810 | .9894 | −0.0010 **p=.77** |
| `CoST-W144-order` | 공유 64 | ✓ | .9256 | .8717 | .9743 | .9936 | +0.0124 p=.0056 |
| `CoST-W144-order-h116` | 공유 **116** | ✓ | .9238 | .8687 | .9727 | .9936 | +0.0106 p=.0115 |
| **`CoST-dual-T144-S144`** | **분리 64×2** | ✓ | **.9285** | **.8769** | **.9775** | .9935 | **+0.0153 p=.0001** |

**용량을 맞춘 근거**: trunk 파라미터는 `hidden_dims` 64 에서 **637,248** 이다.
이원 trunk 는 그것을 둘 가지므로 **1,274,496**. `hidden_dims=116` 이면 공유 trunk 한 개가
**1,266,552** 로 그 **99.4%** 가 된다 (1.988배). 즉 공유 116 과 분리 64×2 는 trunk 용량이 같다.

> 참고 — "파라미터 2배" 는 오해를 부르는 표현이다. 이원 trunk 의 총 파라미터는 33.1M vs 17.4M
> 이지만, **학습되는 것은 14.67M → 15.31M (+4.4%)** 뿐이다. 차이는 trunk 하나(637,248)이고
> 나머지 16.8M(trend trunk 의 `sfd`, seasonal trunk 의 `tfd`)은 forward 에서 계산만 되고 버려져
> **gradient 가 0** 이다. 파라미터는 `tfd` 13.06M + `sfd` 3.75M(창 144) 또는 0.98M(차수 36)에 몰려 있고
> trunk 는 전체의 3.7% 다.

### 4.3 세 짝 비교 (같은 fold × seed, n=25, Wilcoxon)

| 비교 | 묻는 것 | F1(ns) | AUPRC | AUROC | 보존률 |
|---|---|---|---|---|---|
| `order-h116` − `order` | **용량만 2배** (분리 없음) | −0.0018 (11/14) **p=.49** | −0.0030 **p=.46** | −0.0017 **p=.60** | −0.0000 p=.28 |
| `dual` − `order` | **분리만** (용량 +4.4%) | **+0.0029** (18/7) p=.0056 | **+0.0052** p=.0023 | **+0.0032** (20/5) p=.0010 | −0.0001 p=.0015 |
| **`dual` − `order-h116`** | **같은 용량, 분리 vs 공유** | **+0.0047** (20/5) **p=.0002** | **+0.0082** (20/5) **p=.0002** | **+0.0049** (21/4) **p=.0001** | −0.0001 p=.012 |

읽는 법:

1. **공유 trunk 를 2배로 키우면 아무 일도 일어나지 않는다.** 차수 있는 쪽 p=0.49,
   차수 없는 쪽도 −0.0010 (p=0.77). **용량 설명이 배제된다.**
2. 같은 용량에서 분리가 공유를 **네 지표 중 세 개에서 p<0.001 로** 이긴다.
3. 분리 vs 공유64 (+0.0029)보다 분리 vs 공유116 (+0.0047)의 차이가 **더 크다** —
   공유 구조에서는 용량을 늘리는 것이 오히려 약간 해롭다.

### 4.4 메커니즘 증거 — 두 손실이 trunk 를 서로 다른 방향으로 민다

체크포인트에서 "데이터가 가중치를 얼마나 움직였나" 를 쟀다 (같은 seed → 같은 초기값,
fold 1 vs fold 2 의 상대 L2 거리. seed 를 바꾸면 거리가 $\sqrt2$ ≈ 1.41 로 초기값이 지배한다).

| | 데이터 기인 이동량 |
|---|---|
| 공유 trunk (`CoST-W144-order`) | **0.00477** |
| 분리: trend trunk | 0.00232 |
| 분리: seasonal trunk | 0.00022 |
| 분리 둘의 **합** | 0.00254 |

**공유 trunk 가 분리된 둘의 합보다 1.9배 더 움직인다.** $\alpha=0.0005$ 로 손실 *값* 은 작아도
$\partial\mathcal{L}_{\rm season}/\partial\text{trunk}$ 는 작지 않다는 뜻이다.

> ⚠️ **이 측정에서 끌어낸 "교차 압력이 해롭다" 는 해석은 2026-10-29 `sg` 실험으로 기각됐다.**
> stop-gradient 로 seasonal → trunk gradient 를 **완전히 차단**했는데
> (단위 검증: trunk gradient 7.05 → **0.000000**) 결과가 **전혀 바뀌지 않았다**
> (`order-sg` − `order`: F1 +0.0002 **p=0.88**, AUROC +0.0002 p=0.39).
> **즉 그 추가 이동은 성능에 무해했다.** 이동량이 컸다는 사실은 맞지만, 그것이 해롭다는 추론이
> 틀렸다. 올바른 설명은 §4.7(3) 에 있다 — 문제는 gradient 의 **방향**이 아니라 trunk 가
> **어디로 최적화되는가** 다.
>
> 이 절은 **"상관을 메커니즘으로 읽으면 안 된다" 는 사례로 남긴다.** 같은 실패가
> `aux_r2` 에서도 있었다 (§2.3).

### 4.5 기존 ablation 과의 관계 — "seasonal 은 승객" 이라는 해석은 반증되어 있다

`06_cost_ablation` 의 표현 성분 분해 (재학습 없이 같은 모델의 표현을 잘라 평가):

| | 차원 | F1(ns) | AUROC | full 대비 |
|---|---|---|---|---|
| Full (trend160 + season160) | 320 | .9132 | .9782 | — |
| Trend only | 160 | .9089 | .9591 | F1 −0.0044, **AUROC −0.0191** |
| Season only | 160 | .8947 | .9634 | F1 −0.0185, AUROC −0.0148 |

**seasonal 분기는 출력에 실제로 기여한다.** trend 만 쓰면 AUROC 가 −0.0191 떨어진다.
그래서 "seasonal 은 쓸모없는 승객이라 분리해도 상관없다" 는 설명은 쓸 수 없다.
분리가 듣는 이유는 seasonal 이 무용해서가 아니라 **공유 trunk 에서 서로 간섭하기 때문**이다.

### 4.6 분리 방식의 설계 공간 — 지금 것은 가장 극단이다

현재 구현(`CoST-dual-*`)은 **완전히 독립된 두 인코더**로, 공유↔분리 스펙트럼의 한쪽 끝이다.
사이에 설계 공간이 있고, 어느 지점이 필요한지는 아래로 갈린다.

| 설계 | 파라미터 | trunk 를 만드는 손실 | seasonal 이 읽는 특질 | 상태 |
|---|---|---|---|---|
| 완전 공유 (원본 CoST) | 1× | $\mathcal{L}^{\rm MoCo} + \alpha\mathcal{L}_{\rm season}$ | 두 손실이 만든 것 | 완료 |
| **stop-gradient** (`sg`) | **1× (증가 0)** | $\mathcal{L}^{\rm MoCo}$ 만 | **trend 가 만든 것** | **실행 중 (2026-10-29)** |
| 부분 공유 (하위 $k$층만) | 1~2× | 깊이에 따라 | 중간 | **추후** (§6) |
| 완전 분리 | +637k | 각자 | 자기 trunk (초기값 근처) | 완료 |
| 분리 + **동결** (`freeze`) | +637k (절반 고정) | trend 쪽만 | **무작위 초기값** | **실행 중 (2026-10-29)** |

**stop-gradient 가 가장 값진 이유** — `sfd` 진입 직전에 trunk 출력을 `detach` 한다 (forward pre-hook
한 줄, 원본 forward 복사 불필요). **파라미터가 전혀 늘지 않으므로 용량 교란이 원천적으로 없고**,
§4.4 에서 측정한 교차 압력만 제거한다. 분리와 같은 성능이면 원인이 '용량' 도 '구조' 도 아니라
**gradient 간섭** 하나로 좁혀지고, 주장이 "backbone 을 쪼개야 한다"(무거움)에서
**"seasonal 손실이 backbone 을 오염시킨다 — 한 줄로 고칠 수 있다"**(가볍고 강함)로 바뀐다.

단위 검증 (합성 입력, `season.abs().mean()` 역전파):

| | seasonal 손실 → **trunk** | seasonal 손실 → `sfd` | trend 손실 → trunk |
|---|---|---|---|
| 원본 | 7.0495 | 97.393 | 33.013 |
| `sg` | **0.000000** | 97.393 (그대로) | 33.013 (그대로) |

trunk 로 가는 seasonal 경로만 끊기고 `sfd` 는 그대로 학습한다.
(이 수치는 훅의 동작을 확인한 것이고, 실제 학습에서의 상대 크기는 §4.4 의 가중치 이동량이 말한다.)

**동결(`freeze`)과 stop-gradient 는 스펙트럼의 양 끝이라 짝을 이룬다** — 둘을 같이 보면
"seasonal 분기가 필요한 것이 ⓐ **자기 trunk** 인가 ⓑ **오염되지 않은 gradient** 인가" 가 갈린다.

### 4.7 동결·차수없는분리 결과와 그 의미 (2026-10-29)

| 변형 | trunk | 차수 | F1(ns) | AUPRC | AUROC | 보존률 | baseline 대비 F1 |
|---|---|---|---|---|---|---|---|
| baseline | 공유 | — | .9132 | .8525 | .9782 | .9903 | 기준 |
| `order` | 공유 | ✓ | .9256 | .8717 | .9743 | .9936 | +0.0124 p=.0056 |
| `dual-T144-S144` | 분리 | ✓ | .9285 | .8769 | .9775 | .9935 | +0.0153 p=.0001 |
| **`dual-T144-S144-frz`** | **분리 (seasonal 분기 동결)** | ✓ | **.9303** | **.8802** | **.9807** | .9932 | **+0.0171 p<.0001** |
| `dual-T144-S144-noord` | 분리 | **—** | .9150 | .8559 | .9801 | .9903 | +0.0018 **p=.13** |

#### (1) 동결 — 예측을 넘어섰다. **학습시키는 것이 해롭다**

`dual-frz` − `dual` (같은 fold × seed, n=25):

| F1(ns) | AUPRC | AUROC | 보존률 |
|---|---|---|---|
| **+0.0018** (18/7) p=.0105 | **+0.0033** (19/6) p=.0067 | **+0.0032** (24/1) **p<.0001** | −0.0003 (0/22) p<.0001 |

§4.4 에서 분리된 seasonal trunk 의 이동량이 0.00022 였으므로 **"얼려도 같을 것"** 이 예측이었다.
결과는 **유의하게 더 좋다.** AUROC 24/25 가 가장 선명하다.

> **의미**: seasonal 분리기가 필요한 것은 **학습된 특질이 아니라 trend 과제에 오염되지 않은
> 특질**이다. 무작위 초기값으로 충분하고, **학습시키면 나빠진다.**

**범위를 정확히 해둘 것** — `freeze` 는 seasonal **trunk 만** 얼린 것이 아니다.
`for p in m.net_s.parameters(): p.requires_grad = False` 로 **seasonal 인코더 전체**
(trunk 637k + order `sfd` 976k + 쓰이지 않는 `tfd`)를 얼린다. 즉 **seasonal 분기가 완전한
무작위 특질 추출기**다 — 각도축 재표본화도, 차수 bin별 복소 가중치도 전부 초기값이다.
그런데도 그 출력이 표현의 절반(160/320)을 차지하며 1위를 만든다.

**가장 강한 부수 결과 — 1위가 가장 적게 배운다**

| 변형 | gradient 를 받는 파라미터 | baseline 대비 |
|---|---|---|
| baseline (공유, Hz sfd) | 17,443,808 | 기준 |
| `order` (공유, order sfd) | 14,670,368 | −16% |
| `dual` (분리) | 15,307,616 | −12% |
| **`dual-frz`** (분리 + seasonal 동결) | **13,694,528** | **−21%** |

**1위 변형이 baseline 보다 3.75M(−21%) 적게 배웁니다.** §4.2–4.3 에서 용량 설명을 배제했는데,
동결판은 그보다 더 강하게 배제한다 — **학습 용량을 줄이면서 성능이 올라간다.**
"파라미터를 늘려서 좋아진 것" 이라는 반론이 이 변형에서는 성립하지 않는다.

**유일한 역방향 신호** — 보존률이 −0.0003 으로 미세하지만 **0/22 (동점 제외 전부 악화)** 로
완벽히 체계적이다. 크기는 무시할 수준이나 방향은 분명하므로 논문 표에 함께 적는다.

#### (2) 차수 없는 분리 — **차수가 있어야 분리가 듣는다**

`dual-noord` − baseline: F1 +0.0018 **p=.13**, AUPRC +0.0034 **p=.13**,
AUROC +0.0019 **p=.49**, 보존률 −0.0000 **p=1.00**. **전부 유의하지 않다.**

| 조건 | 분리 효과 |
|---|---|
| 차수 **있음** | `dual` − `order` = +0.0029 (18/7) **p=.006** ✓ |
| 차수 **없음** | `dual-noord` − baseline = +0.0018 (16/9) **p=.13** ✗ |

> **의미 — 주장의 범위가 좁혀진다.** "CoST 의 공유 backbone 이 일반적으로 해롭다" 는 쓸 수 없다.
> 측정에 맞는 서술은 **"차수 축 재색인은 전용(그리고 학습되지 않은) trunk 를 요구한다"** 다.

**그런데 이것이 이야기를 오히려 일관되게 만든다 — 축 불일치가 원인이다**

| | 읽는 축 | 공유 trunk 와의 관계 |
|---|---|---|
| `tfd` (trend) | **시간축** | trunk 를 `L_MoCo` 로 자기 축에 맞게 만든다 |
| 원본 Hz `sfd` | **시간축** (FFT 만 함) | trend 와 **같은 축** → 충돌이 작다 |
| **order `sfd`** | **각도축** (재표본화 후 FFT) | trend 가 시간축에 최적화한 특질을 **각도축으로 비튼다** → 충돌 |

공유 trunk 는 거의 전적으로 `L_MoCo`(trend, 시간축)가 만든다. 원본 Hz `sfd` 는 같은 시간축을
쓰므로 그 특질을 그대로 받아도 무리가 없다 — 그래서 차수 없는 분리가 이득이 없다.
반면 order `sfd` 는 받은 특질을 **다른 축으로 재표본화**하므로, 시간축 전용으로 변형된 특질이
각도축에서 의미를 잃는다. 전용 trunk 를 주면 그 변형을 피한다.

**동결이 더 좋은 것도 같은 방향이다** — 전용 trunk 를 **학습시키면** $\alpha=0.0005$ 의 약한
`L_season` 이 그것을 조금씩 각도축 쪽으로 끌어당기는데, 그 양이 너무 작아 **어설픈 중간 상태**가
된다. 아예 무작위로 두는 것이 차라리 깨끗하다. (§4.4 의 이동량 0.00022 가 그 "조금씩" 의 크기다.)

#### (3) stop-gradient 와 하이브리드 — 둘 다 기각, 그리고 메커니즘 확정

**`sg` (stop-gradient) — 아무 일도 일어나지 않는다**

| 비교 | F1(ns) | AUPRC | AUROC | 보존률 |
|---|---|---|---|---|
| `order-sg` − `order` (차수 있음) | +0.0002 (11/11) **p=.88** | +0.0004 p=.30 | +0.0002 p=.39 | +0.0000 p=.86 |
| `noscaleshift-sg` − baseline (차수 없음) | +0.0001 (12/11) p=.32 | +0.0004 p=.024 | +0.0002 p=.0003 | −0.0000 p=.10 |

차수 없는 쪽에서 AUROC p=0.0003 이 나오지만 **크기가 +0.0002** 로 무의미하다.
구현은 정상 작동했다 — 단위 검증에서 seasonal 손실 → trunk gradient 가 7.05 → **0.000000**,
`sfd` 자신의 gradient 는 97.393 그대로, trend 경로도 33.013 그대로였다.

**이것이 §4.4 의 "교차 압력" 가설을 직접 반증한다.** 간섭을 완전히 없애도 성능이 안 바뀐다.

**`dual-frz` − `sg` 가 진짜 원인을 가린다**

| F1(ns) | AUPRC | AUROC | 보존률 |
|---|---|---|---|
| **+0.0046** (20/5) p=.0003 | **+0.0082** (18/7) p=.0003 | **+0.0062** (24/1) **p<.0001** | −0.0004 (1/21) p=.0001 |

| | seasonal 이 읽는 특질 | trunk 가 seasonal gradient 를 받나 | 결과 |
|---|---|---|---|
| `order` | 공유 trunk — `L_MoCo` 가 trend 과제에 최적화 | 받는다 | +0.0124 |
| `sg` | 공유 trunk — **여전히 trend 최적화** | 안 받는다 | +0.0125 (= `order`) |
| `dual-frz` | 전용 trunk — **무작위, 최적화 안 됨** | 안 받는다 | **+0.0171** |

> **메커니즘 확정**: 문제는 gradient 의 **방향**이 아니라 trunk 가 **어디로 최적화되는가** 다.
> `sg` 로 막아도 trunk 는 여전히 `L_MoCo`(trend, **시간축**)가 만들고, 그 시간축 최적화된 특질을
> **각도축으로 재표본화**하면 의미를 잃는다. 그래서 **오염되지 않은 특질이 필요하고,
> 무작위면 충분하며, 학습시키면 오히려 나빠진다.**

**`order-hz` (B2 하이브리드) — Hz 를 더하면 order 가 희석된다**

| 비교 | F1(ns) | AUPRC | AUROC | 보존률 |
|---|---|---|---|---|
| vs baseline | +0.0049 (16/9) **p=.096** | +0.0079 p=.096 | −0.0018 p=.40 | +0.0015 (23/2) p<.0001 |
| **vs `order` 단독** | **−0.0075 (3/22) p<.0001** | **−0.0112 (2/23) p<.0001** | +0.0020 (19/6) p=.012 | −0.0018 (0/25) p<.0001 |

속도별로 order 의 이득이 **전 속도에서 반 이하로 깎인다** (V=125 +0.0345 → +0.0123,
V=50 +0.0114 → −0.0010). AUROC·보존률만 조금 오르고 판정이 나빠진다.

원인 후보 둘 — ① `sfd` 파라미터가 Hz 쪽이 3.8배(3.75M vs 0.98M)라 **합산 결과가 Hz 에 지배**되어
order 축 변별력이 묻힌다 ② §4.6 에 적어둔 대로 더한 시퀀스에서 **인덱스의 의미가 두 분기에서
다르다**(시간 $j$ vs 회전 위상 $j/144$).

**transient 가 시간 고정이라는 측정(§2.0)은 여전히 맞지만, 그것을 "Hz 분기를 되살려 더하기" 로
메우는 것은 작동하지 않는다.** 채널 concat(B1)이 인덱스 혼합을 피하는 대안이지만 희석 문제는
B1 에서도 생긴다 (order 축이 80채널로 줄어듦).

#### (4) 종합 — §4 의 주장을 좁혀야 한다

| | 수정 전 (2×2 격자만 보고) | **수정 후 (1·2순위 반영)** |
|---|---|---|
| 주장 | CoST 의 공유 backbone 이 이 과제에서 해롭다 | **차수 축 재색인은 전용·비학습 trunk 를 요구한다** |
| 근거 | 같은 용량 공유 p=.49 vs 분리 p=.0002 | + 차수 없는 분리는 p=.13 (무효) |
| 메커니즘 | 두 손실의 교차 압력 | **축 불일치** — 시간축 특질을 각도축으로 비트는 충돌 |
| 최선 변형 | `dual-T144-S144` (+0.0153) | **`dual-T144-S144-frz` (+0.0171)** |

좁아졌지만 **기여는 약해지지 않는다** — "원 논문의 disentangle 설계는 두 분리기가 같은 축을
볼 때만 성립하고, 한쪽을 물리적으로 의미 있는 다른 축으로 옮기면 backbone 공유가 깨진다" 는
구조적 지적이고, 그 분리기가 **학습조차 필요 없다**는 결과가 따라붙는다.

| 분리 + 용량을 baseline 과 동등 (각 trunk 폭 ≈45) | 용량 설명을 반대 방향에서 재확인 | 미실행 (§4.2–4.3 이 이미 배제했으므로 생략 가능) |
| 부분 공유 깊이 스캔 | 어느 깊이까지 공유해도 되는가 | **추후 할일** (§6 P12) |
| order 재표본화 앤티앨리어싱 | 저속 4배 다운샘플의 앨리어싱이 해로운가 | **추후 할일** (§6 P14) |

#### ⚠ 반드시 채워야 하는 빈칸 — 분리 × 동결 × 차수의 2×2

| | 차수 **있음** | 차수 **없음** |
|---|---|---|
| **학습** | `dual-T144-S144` **+0.0153** (p=.0001) | `dual-T144-S144-noord` +0.0018 (**p=.13**) |
| **동결** | `dual-T144-S144-frz` **+0.0171** (p<.0001) | **미실행** ← 빈칸 |

**왜 중요한가** — 최선 변형은 seasonal 분기 **전체**가 동결이다. 즉 각도축 재표본화도,
차수 bin별 복소 가중치도 **전부 무작위 초기값**이다. 그러면 "차수 정규화가 기여한다" 는
주장의 근거가 `dual-noord`(학습판, p=0.13) 하나뿐인데, **그건 동결판이 아니다.**

| `dual-noord-frz` 결과 | 결론 |
|---|---|
| ≈ `dual-frz` (+0.017) | **차수는 무관**하고 이득이 "동결된 무작위 seasonal 분기" 에서만 온다 → 주장이 크게 바뀐다 |
| ≈ baseline | **차수가 필수**다 — 동결 상태에서도 각도축 재표본화(고정된 물리 기반 변환)가 일한다 → 현 주장 유지 |

후자가 예측이지만(각도축 재표본화는 학습과 무관한 고정 변환이므로) **재보지 않았다.**
`python code/04_proposed/04_cost_dual_trunk.py tension nrot=1 noorder freeze` → 12분.
방법 이름은 `CoST-dual-T144-S144-noord-frz` 로 자동 분리된다.

### 4.9 창 분리는 **해롭다** — 함께 묶지 말 것

P5 는 원래 "분기별로 **창**을 나누면 시간–주파수 상충이 해소된다" 는 가설이었다(§3.2). **기각됐다.**

| | trunk | 창 | F1(ns) 차이 |
|---|---|---|---|
| `CoST-dual-T144-S288` | 분리 | trend 144 / **seasonal 288** | **−0.0332** (4/21) |
| `CoST-dual-T144-S144` | 분리 | 둘 다 144 | **+0.0153** (22/3) |
| 둘의 직접 짝 비교 | | | **+0.0485** (24/1, p<.0001) |

**창 288 로 가는 것이 −0.0485 짜리 손해다.** 틀린 전제는 "시간 국소화는 trend 의 일" 이라는
분업 가정이었다 — 최종 표현이 `season[:, -1]` 이고 GMM 이 **시점별로** 분류하므로
**seasonal 표현도 시점별 기술자**다. 창 288 이면 차수 해상도와 무관하게 7~18 s transient 의
경계를 흐린다. 시간–주파수 상충은 분기를 갈라도 **seasonal 분기 안에 그대로 남는다.**

> 즉 P5 에는 두 가지가 섞여 있었고 결과가 반대 방향이었다 — **창 분리는 해롭고 trunk 분리는 이롭다.**

### P13 — Hz + order 하이브리드 (실행 중)

**근거**: §2.0 에서 측정한 대로 롤러 교란은 **각도 고정**이고 transient 는 **시간 고정에 훨씬
가깝다**. order 축으로 전부 재색인하면 방해물은 고정되는 대신 **표적이 bin 사이를 움직인다.**
현재 `CoST-W144-order` 는 Hz sfd 를 **버리고** seasonal 160 채널 전부를 order 축에서 뽑는다.

**설계 (B2 합산)** — `sfd` 를 두 개 두고 출력을 **element-wise 로 더한다.**

```
trunk 출력 (B,144,320) ─┬─ Hz sfd    (원본, 73 bin) → (B, 144, 160)
                        └─ order sfd (19 bin)       → (B,  36, 160)
                                                          │ 길이축 되돌리기 36→144
                                                          ▼
                                              season = 합  (B, 144, 160)
```

- 되돌리기는 **길이축만** 바꾸고 채널 160 은 손대지 않는다. `align_corners=True` 라 **마지막 시점
  값이 불변**이므로 표현(`season[:, -1]`)은 되돌리기 방식에 무관하다
- 되돌리기를 **균일 보간**으로 한다 — order 영역 시퀀스는 이미 "1회전 = $L_{\rm ORD}$ 샘플" 로
  속도 정규화돼 있고, 균일 보간은 "1회전 = 창 길이" 로 그 성질을 유지한다. (잘라낸 길이 $w$ 로만
  되돌리고 앞을 패딩하면 **속도별 패딩 길이가 손실에 새 단서를 준다**)
- 구현은 Hz `sfd` 에 **forward hook** 을 걸어 같은 trunk 출력으로 order 분기를 계산해 더한다
  (원본 `forward` 를 복사하지 않는다). hook 은 `deepcopy` **뒤에** 질의 인코더에만 건다 —
  키 인코더의 seasonal 출력은 원본에서 쓰이지 않는다 (`_, k_s = self.encoder_q(x_k)`)

**단위 검증 통과**: season 모양 (B,144,160), 합산 효과 L2 9.35 (≠0), **trend 영향 L2 0.000000**,
`deepcopy` OK. 파라미터 `sfd` 4.73M (order 단독 0.98M 의 4.8배), 인코더 전체 **+25.6%**.

**주의 — 두 가지**
1. 더한 시퀀스가 손실의 `rfft(q_s, dim=1)` 에 들어간다. 인덱스 $j$ 의 의미가 두 분기에서
   다르므로(시간 $j$ vs 회전 위상 $j/144$) **손실이 보는 시퀀스는 두 축의 혼합**이다.
   표현(마지막 시점)에는 이 문제가 없다. **채널 concat(B1, Hz 80 + order 80)이 이 혼합이 없는 대안**이고,
   B2 결과를 보고 필요하면 비교한다
2. `sfd` 파라미터가 4.8배다. 다만 `sfd` 는 모델의 작은 부분이라 인코더 전체로는 +25.6% 이고
   (trunk 때의 2배 규모가 아니다), 필요하면 용량 대조군을 따로 둔다

### P14 — order 재표본화 앤티앨리어싱 (추후 할일)

**문제**: `OrderBandedFourierLayer` 의 재표본화가 `F.interpolate(mode='linear')` 인데
**앤티앨리어싱을 하지 않는다.**

| V | 재표본화 | 앨리어싱 |
|---|---|---|
| 200 | 36 → 36 (변화 없음) | 없음 |
| 100 | 72 → 36 (2배) | 차수 18 이상이 접힘 |
| **50** | **144 → 36 (4배)** | **차수 18~72 가 0~18 로 접힘** |

저속에서 고차수 성분이 저차수로 접혀 들어온다. 롤러 교란(차수 1)이 중앙값 파워의 600~1300배라
상대적 영향은 작을 것이고 실제로 저속에서 AUROC 가 개선되므로 **해롭다는 증거는 없다.**
다만 아직 재보지 않았다.

**설계**: `interpolate` 를 **저역통과 후 다운샘플**로 바꾼다 (예: `antialias=True` 또는 명시적 필터).

**비용**: 구현 10분 + 실행 12분. 창을 바꾸지 않으므로 학습량 자동 동등.

**중요 — P13 과 묶지 않는다** (연구자 결정 2026-10-29). 둘을 함께 바꾸면 기존
`CoST-W144-order`(+0.0124) 와의 비교가 교란된다. **각 변경을 같은 기준에 대해 따로 재는 것**이
지금까지 지켜온 "한 번에 하나만 바꾼다" 와 일관된다. P14 는 P13 의 선행 작업이 아니라
**독립된 변형**이다.

### P12 — 부분 공유 깊이 스캔 (추후 할일)

**묻는 것**: "공유가 해롭다" 를 **"어느 깊이까지 공유해도 되는가"** 로 정밀하게 만든다.

**설계**: trunk 의 `DilatedConvEncoder` 10층 중 **앞 $k$층만 공유**하고 뒤 $10-k$층을
trend·seasonal 분기별로 둔다. $k=10$ 이 완전 공유(원본), $k=0$ 이 완전 분리(`CoST-dual-*`)다.
$k \in \{0, 3, 5, 7, 10\}$ 를 스캔하면 간섭이 **어느 깊이에서 생기는지**가 드러난다.

**가치**: 얕은 층은 공유해도 되고 깊은 층만 갈라야 한다면, 파라미터 증가를 최소화하면서 같은
이득을 얻는 설계가 나온다. 또 "저수준 특질은 공통이고 고수준에서 과제가 갈린다" 는
multi-task 학습의 표준 그림과 맞는지도 확인된다.

**비용**: 5변형 × 12분 = 약 1시간 + 구현 반시간. 창을 바꾸지 않으므로 학습량은 자동 동등하다.

**선행 조건**: P10(stop-gradient) 결과를 먼저 본다. stop-gradient 가 완전 분리와 같은 성능이면
원인이 **gradient 간섭** 으로 좁혀지고, 그때는 "어느 깊이에서 갈라야 하나" 보다
"어느 깊이까지 gradient 를 막아야 하나" 가 더 맞는 질문이 된다 (같은 스캔 틀을 쓰면 된다).

### 실험 범위와 동등 비교 (연구자 결정 2026-10-29)

- **제안 방법의 실험은 A 까지만** 진행한다. C 실험·ambiguous 포함 재채점은 하지 않는다.
- **학습량은 언제나 baseline 과 동등해야 한다.** 창을 바꾸는 변형은 `max_train_length` 가 run 을
  쪼개는 조각 수를 바꿔 1 epoch 의 iteration 수가 달라지므로(§11 문제 9), 같은 iteration 수를 쓰면
  **데이터 통과 횟수가 어긋나 비교가 깨진다.** 통과 횟수를 맞추는 `n_iters` 를 유도해서 쓴다 —
  `n_iters = 600 × (조각수_변형 / 조각수_baseline)`. P5 의 창 288 분기는 600 × 4/9 = **267**
  (대조군은 창이 144 라 조각 수가 같아 600 그대로). 제안 방법이 갱신 횟수가 줄어 덜 학습되는
