# Coding Guidelines

본 연구의 코드 구현 시 반드시 지켜야 할 유의사항. 이 코드는 소프트웨어 개발 용도가 아니라 **데이터 분석 용도**이다.

---

## 1. Hyperparameter
- 사용자가 지정할 수 있는 hyperparameter는 **코드 상단에 모아서 배치**한다.
- hyperparameter는 최소화한다. **동일한 역할을 하는 hyperparameter는 반드시 동일한 이름으로 1개만** 생성한다.

## 2. 함수화
- 함수화는 지양한다.
- 다만 반복적으로 사용되는 코드는 함수로 만들 수 있으며, 생성된 함수는 **코드 상단(hyperparameter 아래)** 에 배치한다.
- 각 함수에는 **역할/포함된 내용, 입력, 출력 정보**를 주석으로 추가한다.

## 3. 파일 구성
- 코드 파일은 **제안 방법(제안 모델).py** 와 **비교군.py** 로 구분한다.
- 모든 비교군을 한 파일에서 다루거나, 비교군마다 하나의 .py 파일로 구성할 수 있다.
- 단, **제안 모델과 비교군은 반드시 서로 다른 .py 파일**이어야 한다.

## 4. 주석
- 코드의 **블록 단위(역할/기능 단위)** 로 어떤 내용의 코드인지 주석을 추가한다.
- 임의로 설정한 값이 있다면, 해당 라인의 주석에 **"임의의 값"** 이라고 표기한다.

## 5. 사전 승인
- 코드 구현 시 사용자가 결정해야 하는 내용이 있다면, **구현하기 전에 허락**을 받는다.
- 새로운 아이디어나 분석 중간에 시도해볼 만한 아이디어는 제안할 수 있으나, **구현은 언제나 사용자가 지시한 사항만** 수행한다.
- feature extraction, thresholding, 평가 방식 설정 등을 **임의로 정하여 구현하지 않으며**, 반드시 사전 검토를 받는다.

## 6. 결과물
- 모든 중간/최종 결과물은 **csv file 또는 plot**으로 저장한다.
- plot은 논문에 바로 넣을 수 있도록 **논문 스타일**(예: grid 추가 등)로 구성한다.
- `print()` 문을 적극 활용하여 각 단계의 중간 결과를 확인할 수 있게 한다.

## 7. 예외 처리
- 예외 처리 코드는 최소화(지양)한다.
