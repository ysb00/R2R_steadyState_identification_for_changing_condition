### 3.1 보정판 2종 — `R-test-calibrated` / `R-test-decimated-calibrated` (2026-10-26)

원 논문 고정 임계값 2.5/0.9 대신 **학습 fold 에서 임계를 정한다.** R 1차원을 '표현' 으로 보고
다른 모든 비교군과 **동일한** 트랙 A 후단(표준화 + 2-군집 GMM -> |e 평균| 작은 군집 = steady)에
넣는다. MovStd-Slope 가 임계값을 손으로 정하지 않는 방식과 같은 구조이고(`outputs_guide.md` §10.3.3),
라벨을 쓰지 않으며 **새 임의값이 생기지 않는다**(분위수를 고르면 임의값이 2개 늘어난다).

원 샘플링·다운샘플링 **둘 다** 보정해 2x2 로 둔다 — 한쪽만 보정하면 그 선택이 새 임의값이 된다.

| 방법 | 오염률 | 보존률 | AUROC | AUPRC(ns) | F1(ns) | 진입 bias | 진입 미검출 run |
|---|---|---|---|---|---|---|---|
| `R-test` (9 Hz, 원 논문) | 1.000 | **0.000** | 0.698 | 0.355 | 0.149 | −23.4 s | **41.4 / 42** |
| `R-test-calibrated` (9 Hz) | 0.063 | **0.972** | 0.692 | 0.351 | 0.327 | −18.6 s | **0** |
| `R-test-decimated` (원 논문) | 0.021 | **0.174** | 0.901 | 0.579 | 0.167 | +27.6 s | **22 / 42** |
| `R-test-decimated-calibrated` | 0.021 | **0.887** | **0.910** | 0.545 | 0.506 | −19.5 s | **0** |

**2x2 가 두 효과를 분리한다.** 샘플링 전제가 바꾸는 것은 **분리력**(AUROC 0.69 -> 0.91, 보정 여부와 무관),
임계값 보정이 바꾸는 것은 **작동점**(보존률 0.000 -> 0.972 / 0.174 -> 0.887, 미검출 run 전부 0).
즉 깨진 것은 통계량이 아니라 임계값 보정이고, 이는 `research_plan.md` 2절의 연구 동기
("통계 기반 SSI 는 조건별 임계값 재튜닝이 필요하다")의 직접 증거다.

**보정판을 넣어도 결론은 유지된다** — `MovStd-Slope-fixed-rule1b` 가 AUROC 0.957 / AUPRC 0.608 /
F1 0.603 / 진입 bias +2.5 s 로 여전히 전 지표 우위다. 공정하게 비교한 뒤에도 유지되므로 주장이 강해졌다.

**주의 2건.**
- 보정판은 원 논문의 **2-임계값 히스테리시스를 쓰지 않는다.** 트랙 A 후단은 사후확률 >= 0.5 의
  단일 임계이므로, 바뀐 것이 '임계값' 뿐이 아니라 '임계 규칙' 이기도 하다.
- **점수도 바뀐다** (R 통계량 -> GMM 사후확률). 1차원 GMM 사후확률은 R 의 단조함수가 아닐 수 있어서,
  AUROC 가 0.901 -> 0.910 으로 움직인 것은 "임계값만 바꿨다" 로는 설명되지 않는다.

### 문제 9 상세 — 창 효과 vs 학습량 효과

| W | sections | 학습 조각 | iter/epoch | 데이터 통과 횟수 | 본 시점 수 | AUPRC |
|---|---|---|---|---|---|---|
| 160 | 8 | 1,344 | 168 | **3.57회** | 0.77 M | **0.814** |
| 256 | 5 | 840 | 105 | 5.71회 | 1.23 M | 0.533 |
| 306 | 4 | 672 | 84 | 7.14회 | 1.47 M | 0.428 |
| 512 | 2 | 336 | 42 | **14.29회** | 2.46 M | **0.231** |

이 교란 때문에 현재 세 결론이 모두 불확정이다 (아래 (1)~(3)):

1. **CoST 가 1위다**(W=160) — 설계 덕인지 미학습 덕인지 불명
2. **창이 길면 나빠진다** — 창 효과인지 학습량 효과인지 불명
3. **CoST 의 seed 안정성이 TS2Vec·SoftCLT 의 1,000배다**(σ 0.0007 vs 0.2~0.27) — 설계인지 학습 진행도(3.57회 vs 28.6회 통과) 차이인지 불명

**분리 방법**: iteration 수를 맞추는 대신 **데이터 통과 횟수(또는 본 시점 수)를 창 간에 동일하게** 둔다.
예: 통과 횟수를 k 로 고정하면 `n_iters(W) = k × (1300//W) × 168 / 8`. 그러면 창 효과만 남는다.
TS2Vec·SoftCLT 와의 비교에서도 같은 문제가 있다 — 세 방법의 `max_train_length` 가 달라
(CoST = W, TS2Vec·SoftCLT = 3000) 같은 600 iter 에서 통과 횟수가 3.57 ~ 28.6 회로 갈린다.

## 12. 창 길이 규칙 — 규칙 1b 로 통일 (사용자 결정, 2026-10-23)

**지금까지 창 길이가 방법마다 다른 규칙으로 정해져 있었다.** MovStd-Slope 는 임의값 64,
CoST 는 fs 하한 위의 최소 2의 거듭제곱(256), SoftCLT `tau_temp` 는 MovStd 의 64 에서 파생.
이것을 하나의 규칙으로 통일한다.

### 채택한 규칙 (1b)

```
f_rot = V / (π·D)              롤 회전 주파수. V = 속도 설정값, D = 롤 지름 (둘 다 라벨 아님)
W     = ⌈ fs / f_rot(V_min) ⌉  가장 느린 조건(V=50)의 1주기를 담는 최소 창
```

근거와 물리 기전은 `docs/periodic_disturbance.md` 에 정리했다. 핵심:
- **하한**: 창이 1주기보다 짧으면 steady 의 느린 진동이 "추세" 로 보여 비정상으로 오판한다(D1). 실측 확인 — 고정창 64 가 1주기를 못 담는 V=50/75/100 에서 오염률 0.043–0.083 vs 담는 V≥125 에서 0.005–0.017
- **상한 방향**: causal 창은 과도구간을 창 길이만큼 기억해 steady 진입을 늦춘다. 실측 — CoST 진입 bias 가 W=160 에서 −1.7 s, W=512 에서 +35.5 s
- → 하한을 택한다

### 왜 다른 규칙을 버렸는가

| 버린 규칙 | 사유 |
|---|---|
| 최소 2의 거듭제곱 (256) | 유일한 논거였던 rfft 효율이 **측정으로 반박됐다** — 소인수와 forward 속도가 무관하고(153: 6.63 ms, 160: 6.55, 176: 6.77), 256 은 153보다 **1.24배 느리다**. 또 속도별 창에서 7수준이 3수준(256/128/128/64/64/64/64)으로 뭉개져 변형의 취지가 사라진다 |
| 라벨로 측정한 주파수 사용 (1a) | 1.2절 주파수는 "run별 steady 앞 1024 샘플" 에서 측정 — steady 위치를 알아야 하므로 **라벨 사용**이고 `research_plan.md` 0절 위반. 회전 주파수 식으로 대체해 해소한다 |
| 8의 배수 | TS-TCC 의 8배 다운샘플 사정이고 다른 방법과 무관. `features_len` 은 어느 길이에서도 정수로 나오므로 **제약이 아니다** |

### 확정값 — W = 144 samples (15.7 s)

둘레를 라벨 없이 측정해 확정했다 (`docs/periodic_disturbance.md` §6–7, 그림 5종 포함).

```
C     = 783.5 mm            역산 둘레 (205 run 평균, 지름 249.4 mm, 표준편차 13.1 mm)
f_min = 50 / 783.5 = 0.0638 Hz
W     = ceil(9.174 / 0.0638) = 144 samples (15.7 s)       불확실성 +-8 samples
```

속도별 창 변형: `W(V) = ceil(fs·C/V)` = **144 / 96 / 72 / 58 / 48 / 42 / 36**
(현재의 `64×125/V` = 160/107/80/64/53/46/40 은 이 값의 약 1.11배이고, 그 1.11 이 임의 상수 64 에서 나왔다)

부수 결과: 주기 외란의 출처가 **리와인더 롤이 아니라 지름 ≈ 249 mm 의 고정 지름 회전체**임이
밝혀졌고, 따라서 `Rewinder roll diameter` 열은 **모델 입력에 넣지 않는다**(진단 용도로만 사용).

### 창 길이는 144 로 **고정**한다

규칙 1b 로 유도한 `W = 144` 를 **앞으로 모든 창 기반 방법의 기본값으로 고정**한다.
TS-TCC·SimMTM 어댑터, CoST ablation, 제안 방법 모두 이 값을 쓴다.
창 길이 민감도는 이미 CoST 5종(144/160/256/306/512)과 MovStd-Slope 2쌍에 있으므로,
**새 실험에서 창을 다시 탐색하지 않는다.** 바꾸려면 §12 의 유도 자체를 다시 해야 한다.

실측으로도 뒷받침된다 — CoST 창 5종 중 **144 가 Prec(ns) 0.881 / F1 0.902 / AUPRC 0.832 로 최고**다.
규칙에서 나온 값이 결과로도 가장 좋았고, **성능을 보고 고른 값이 아니라는 점이 중요하다.**

### 적용 현황 (2026-10-23)

| 방법 | 창 | 상태 |
|---|---|---|
| `MovStd-Slope-fixed-rule1b` | 144 | ✅ **완료** |
| `MovStd-Slope-speed-rule1b` | `⌈fs·C/V⌉` = 144/96/72/58/48/42/36 | ✅ **완료** |
| `CoST-W144` | 144 | ✅ **완료** — 창 5종 중 전 지표 최고 |
| CoST ablation 2종 (성분 분해 / 증강 제거) | 144 고정 | ⬜ 진행 중 |
| **SoftCLT 2변형** | 창 없음, `tau_temp` 반경 = W/2 | ⬜ **미실행 — 아래 §13.2 B5** |
| TS-TCC, SimMTM | 144 | ⬜ 어댑터 미작성 |
| R-test ×2, TS2Vec, MOMENT | 창 없음 / 구조 강제 | — 해당 없음 |

기존 임의 창 변형(`MovStd-Slope-fixed` W=64, `MovStd-Slope-speed`)은 **지우지 않고 유지한다.**
`periodic_disturbance.md` §7.2 의 창 하한 근거 그림이 그 데이터를 쓰고, 창 길이 효과를 보여주는
대조군 역할을 한다.

### 재실행 범위 — 전체가 아니다

**창을 쓰지 않는 방법은 그대로 유효하다.**

| 방법 | 창 사용 | 규칙 1b 적용 | 재실행 |
|---|---|---|---|
| R-test (9 Hz) | ❌ EWMA 필터, 창 없음 | 해당 없음 | **불필요** |
| R-test (다운샘플) | ❌ 창 없음 | 해당 없음 | **불필요** (단 `RTEST_DECIMATE=10` 은 별개 임의값) |
| TS2Vec | ❌ `max_train_length=3000 > 1300` 이라 run 전체를 본다 | 해당 없음 | **불필요** |
| MOMENT | ⚠️ 512 **구조 강제** | **예외 — 변경 불가** | **불필요** |
| MovStd-Slope 고정창 | ✅ 64 | → W | **필요** (몇 분, GMM 만) |
| MovStd-Slope 속도별창 | ✅ 64×125/V | → `⌈fs/f_rot(V)⌉` | **필요** (몇 분) |
| CoST | ✅ 160/256/306/512 | → W 1종 추가 | **1창 추가** (약 12분, 25회). 기존 4종은 민감도로 유지 |
| SoftCLT | ❌ 창 없음. 단 `tau_temp` 반경 = W/2 | → `tau_temp = ln3/(W/2)` | **필요** (약 90분) — 아래 주의 참조 |
| TS-TCC, SimMTM | ✅ 미착수 | W | 신규 |

**합계 약 2시간** (CoST 12분 + MovStd 몇 분 + SoftCLT 90분). TS-TCC·SimMTM 은 신규라 별도.

**주의 — SoftCLT `tau_temp` 반경은 규칙 1b 가 정해주지 않는다.** "반경 = W/2" 는 내가 정한 규약이고
(`hyperparameters.md` §8), 시간 이웃 반경("두 시점을 같은 상태로 볼 시간 거리")은 "1주기를 담는 창 길이" 와
다른 양이다. 후보: 주기의 1/2(= W/2) / 1/4 / 1주기. **별도 결정이 필요하다.** 반경을 안 바꾸면
SoftCLT 재실행도 불필요하다.

**예상되는 변화**: MovStd-Slope 고정창은 현재 2위이고 저속 오염이 "창이 짧아서" 로 설명됐으므로
W 를 늘리면 개선이 예상된다. 다만 **속도별창은 이미 모든 속도에서 1주기 이상을 담는데도 개선이
없었으므로**(`periodic_disturbance.md` §7) 고정창도 개선되지 않을 수 있다. 이 자체가 정보가 되는 실험이다.

#### B5 상세 — SoftCLT 재실행에 필요한 것

창 규칙 1b 로 `W = 144` 가 확정됐고 MovStd-Slope·CoST 는 반영했다. SoftCLT 만 남았다.

**SoftCLT 는 창을 쓰지 않는다.** `max_train_length = 3000 > 1300` 이라 run 전체를 본다.
영향을 받는 것은 **시간 축 soft label 의 반경** 하나다:

```
현재 : tau_temp = ln3 / 32  = 0.0343      반경 32 샘플 = WINDOW(64)/2   <- 임의값 64 에서 파생
```

**먼저 정해야 할 것**: 반경을 무엇으로 둘지. 창 규칙 1b 는 **"1주기를 담는 창 길이"** 를 주는데,
`tau_temp` 반경은 **"두 시점을 같은 상태로 볼 시간 거리"** 로 다른 양이다. 후보:

| 반경 근거 | 반경 (샘플) | `tau_temp` | 비고 |
|---|---|---|---|
| 창의 절반 (현 규약 유지, W=144) | 72 | **0.0153** | 기존 규약을 그대로 새 창에 적용 |
| 주기의 1/4 | 36 | 0.0305 | 위상이 크게 바뀌기 전까지를 이웃으로 |
| 1주기 전체 | 144 | 0.0076 | 가장 느슨 |
| 현재 (임의 창 64 기준) | 32 | 0.0343 | 유도 근거가 사라졌다 |

**결정하지 않으면 재실행할 수 없다.** 반경 규약을 바꾸지 않기로 하면 재실행 자체가 불필요하다.

**재실행 시 작업**: `05_softclt.py` 의 `VARIANTS` 에서 `SoftCLT-fs` 의 `tau_temp` 를 교체하고,
결과 이름을 구분한다(예: `SoftCLT-fs-rule1b`). `SoftCLT-ref`(저자 표 중앙값 `tau_temp=1.0`)는
창 규칙과 무관하므로 **그대로 둔다.** DTW 행렬은 캐시돼 있어 재계산이 없다.

### 13.3 설정값 전면 재검토 (연구자 방침: 비교군 구현 완료 후)
