# 분할(fold) 정의 — A 실험 / C 실험

fold 가 **어떤 설정값 조건으로** 나뉘고, 각 fold 의 학습·검증에 **어떤 라벨이 몇 개** 들어 있는지를
한곳에 모은 문서다. 정의의 단일 출처는 `code/03_baselines/00_folds.py` 이고, 이 문서의 수치는
`outputs/03_baselines/folds.csv` · `outputs/04_speed_extrap/folds_c.csv` · `outputs/merged_data.csv`
에서 직접 집계한 것이다.

관련 문서 — 설계 근거는 `hyperparameters.md` §13.0, 지표 읽는 법은 `outputs_guide.md`.

---

## 1. 조건 격자 — 분할 규칙을 결정하는 전제

**장력 5수준 × 리와인더 6수준 × 속도 7수준 = 210 조건, 조건당 run 정확히 1개.**

| 설정값 | 약어 | 수준 |
|---|---|---|
| Film-Tension Setting Value (kg) | TS | 3, 4, 5, 6, 7 |
| ReWinder-Tension Setting Value (kg) | RS | 2, 3, 4, 5, 6, 7 |
| Web Speed setting value (mm/sec) | VS | 50, 75, 100, 125, 150, 175, 200 |

조건당 run 이 1개뿐이라 **run 단위 무작위 분할을 쓰지 않는다.** 그렇게 하면 검증 run 과 한 축만
다른 run(예: 같은 장력·리와인더에 속도만 한 칸 옆)이 학습에 들어가 "미학습 조건" 이 성립하지 않는다.
그래서 **설정값 수준(level) 단위로 끊는다.** 난수를 쓰지 않는 결정론적 배정이라 분할에는 시드가 없다
(시드는 GMM 후단과 인코더 학습에만 쓰인다).

**리와인더(RS)는 어느 실험에서도 분할 기준이 아니다** — 항상 학습·검증 양쪽에 6수준 전부 들어간다.

## 2. A 실험 — 장력 leave-one-level-out **5-fold CV**

**질문**: 학습에 없던 **새 장력 설정값**에 일반화되는가.
**규칙**: `fold_tension == f` 인 run 이 검증, **나머지 전부**가 학습. 210 run 을 모두 쓴다(미사용 0).
속도 7수준·리와인더 6수준은 모든 fold 의 학습·검증에 **전부** 들어간다 — 즉 **장력 축만 unseen** 이다.

| fold | 역할 | run | 장력 TS (kg) | 리와인더 RS (kg) | 속도 VS (mm/s) |
|---|---|---|---|---|---|
| **fold 1** | 학습 | 168 | 4, 5, 6, 7 | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
|  | 검증 | 42 | **3** | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
| **fold 2** | 학습 | 168 | 3, 5, 6, 7 | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
|  | 검증 | 42 | **4** | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
| **fold 3** | 학습 | 168 | 3, 4, 6, 7 | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
|  | 검증 | 42 | **5** | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
| **fold 4** | 학습 | 168 | 3, 4, 5, 7 | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
|  | 검증 | 42 | **6** | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
| **fold 5** | 학습 | 168 | 3, 4, 5, 6 | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |
|  | 검증 | 42 | **7** | 2, 3, 4, 5, 6, 7 | 50, 75, 100, 125, 150, 175, 200 |

fold 1(3 kg)·fold 5(7 kg)는 격자 끝이라 **외삽**, fold 2·3·4 는 **내삽**이다.

> `fold_speed`(속도 7-fold)도 `folds.csv` 에 배정만 있고 **실행하지 않았다.** leave-one-out 은 내삽이라
> — 속도 100 을 빼도 학습에 150·175·200 이 남아 "고속을 이미 본" 상태가 된다. 그래서 C 실험을 따로 만들었다.

## 3. C 실험 — 저속 학습 → 미학습 고속

**대전제**: 데이터를 먼저 두 덩어리로 봉인한다.

```
저속  50 / 75 / 100 / 125   = 120 run  ->  학습 + CV 전용
고속  150 / 175 / 200       =  90 run  ->  최종 test 전용 (CV 에서 절대 쓰지 않는다)
```

그래서 CV fold 에서는 **"학습 = 검증 아닌 나머지" 가 성립하지 않는다** — 고속 90 run 은 학습도 검증도
아닌 **미사용(unused)** 이다. A 처럼 fold 번호 하나로 유도할 수 없어, run 마다 역할을
`train` / `val` / `unused` 로 **명시 저장**한다 (`folds_c.csv` 의 `role__*` 컬럼).

### fold 8개의 정체

| 묶음 | 정체 | fold 수 | unseen 축 |
|---|---|---|---|
| `cv_T1`~`cv_T5` | **장력 leave-one-level-out 5-fold CV** (저속 데이터만으로) | 5 = 완결된 CV | **장력** |
| `cv_S1`, `cv_S2` | **속도 누적 외삽 2종.** CV 가 아니다 — 학습량이 서로 다른 독립 설정 | 2 | **속도** |
| `final_test` | 최종 test. 한 번만 쓴다 | 1 | **속도** |

**세 묶음을 가로질러 평균하지 않는다** — 묻는 질문도, unseen 축도, 학습량도 다르다.
집계 스크립트(`12_summary_tables_c.py`)가 `cv_T` / `cv_S1` / `cv_S2` / `final_test` 를 표의 **열로 분리**한다.

### 3.1 `cv_T1`~`cv_T5` — 저속 안에서 **새 장력**에 되는가

A 실험과 **같은 질문을 저속 데이터만으로** 묻는다. 검증 장력만 3→4→5→6→7 kg 으로 돌아가는
하나의 5-fold CV 이고, 집계할 때 5개를 평균해 `cv_T` 한 값으로 보고한다.
속도는 저속 4수준이 학습·검증 양쪽에 있으므로 **속도 축으로는 seen** 이다.

### 3.2 `cv_S1`, `cv_S2` — **속도 1수준 외삽**이 되는가

**"누적 외삽"** 설계다 — 학습 속도를 한 수준씩 늘려가며 **바로 다음 속도**를 검증한다.
검증은 항상 학습보다 빠르고, 외삽 거리는 **1수준(25 mm/s)으로 고정**된다.
final_test 와 방향이 같아 CV 가 test 를 예측하는 근거가 된다.

| | 학습 속도 | 검증 속도 | 학습 run | 외삽 거리 |
|---|---|---|---|---|
| `cv_S1` | 50, 75 | **100** | 60 | 1수준 |
| `cv_S2` | 50, 75, 100 | **125** | 90 | 1수준 |

> **둘은 한 CV 의 두 fold 가 아니다.** 학습량이 60 vs 90 run 으로 달라 평균내면 안 된다.
> `cv_S1` -> `cv_S2` 의 성능 변화를 "외삽이 어려워져서" 로만 읽으면 안 되는 이유다 —
> 검증 속도와 학습량이 **함께** 움직였다.
> 저속이 4수준뿐이라 이 규칙으로 만들 수 있는 fold 는 2개다 (`50 -> 75` 는 학습이 1수준이라 제외).

### 3.3 `final_test` — 최종 목표

**질문**: 저속만 학습하고 **미학습 고속**에 되는가 (`hyperparameters.md` §13.0 의 최종 목표).
저속 4수준 전부로 학습 → 고속 3수준 전부로 평가. **미사용 0.**

`cv_S` 와 다른 점 두 가지 — **외삽 폭이 3수준(75 mm/s)** 이고, 검증에 **속도 3수준이 동시에** 들어간다.
(그래서 조건별 heatmap 을 속도별 패널 3개로 쪼갠다 — 고정된 설정값이 없어 2차원 격자가 성립하지 않는다.)

**분할은 고정 1개, 1회다.** 재분할·반복 CV 가 없다. 단 방법 1종당 seed 5회를 돌리므로
비교군 23종 기준 누적 115회 평가가 **같은 테스트셋**에서 일어났다. 하이퍼파라미터를 이 셋으로 고른
적은 없으나(As-published, 라벨 미사용) **다중비교이므로, 제안 방법의 변형 선택에 쓰면 안 된다** —
쓰는 순간 개발셋이 되어 최종 보고로서의 의미가 사라진다. 변형 선택은 `cv_S1`·`cv_S2` 에서 한다.

## 4. 라벨 개수

> **채점 단위는 window 가 아니라 시점(timepoint) 이다.** window 는 인코더 내부에서만 쓰이고
> (CoST·TS-TCC·SimMTM 144, MOMENT 512), 표현은 시점마다 1개씩 나와 시점 단위로 채점한다.

라벨 모드가 2종이다 (`hyperparameters.md` §13.9):

- **제외** — `Trigger 4 == 2` (ambiguous) 를 채점에서 뺀다. 기본값
- **포함** — ambiguous 를 시간상 **가장 가까운 비-ambiguous 시점의 라벨**로 흡수해 2클래스로 만든다

### 4.1 전체

전체 시점 **268,933** 개 (run 210, run 당 1,275~1,300 샘플, 9.174 Hz)

| 모드 | transient (0) | steady (1) | ambiguous (2) | 채점 대상 | non-steady 비율 |
|---|---|---|---|---|---|
| **제외** | 20,429 | 230,787 | 17,717 (채점 제외) | **251,216** | **0.0813** |
| **포함** | 28,592 | 240,341 | 0 | **268,933** | **0.1063** |

- ambiguous 17,717 개 -> transient **8,163** / steady **9,554**
- 비-ambiguous 251,216 개 중 라벨이 바뀐 것: **0 개**
- 채점 대상 **+17,717 (+7.1%)**

### 4.2 fold 별

`ns 비율` = **non-steady 비율** = `transient ÷ (transient + steady)` = 채점 대상 중 transient 의 비율.
`제외` 열은 ambiguous 를 뺀 분모, `포함` 열은 흡수 후의 분모(= 그 fold 의 전 시점)로 계산한 값이다.

**이 값이 곧 AUPRC(ns) 의 기준선**(무정보 분류기의 성능)이다. 그래서:

- **fold 간 AUPRC 비교 ✗** — 아래 표에서 검증 ns 비율이 0.025~0.111 로 4배 넘게 차이난다
- **두 모드 간 AUPRC 비교 ✗** — 기준선이 0.0813 -> 0.1063 으로 움직인다
- **AUROC 는 두 경우 모두 비교 가능** — 클래스 대칭이라 유병률에 영향받지 않는다

## 5. 요약 — 어떤 fold 를 어디에 쓰나

| 쓰임 | fold | 비고 |
|---|---|---|
| 전체 조건에서의 일반 성능 | **A 5 fold × 5 seed** | 210 run 전부를 쓰는 유일한 CV. 변동폭 추정 가능 |
| 저속 한정 장력 일반화 | C `cv_T1`~`cv_T5` | A 와 같은 질문, 데이터는 저속만 |
| **속도 일반화 — 변형 선택** | C `cv_S1`, `cv_S2` | **fold 2개뿐이라 선택 신호가 약하다** |
| 최종 보고 | C `final_test` | **한 번만.** 변형 선택에 쓰지 않는다 |
| 조건별 취약점 | 속도별로 쪼갠 표 | `_final_test_by_speed.csv`. 평균이 숨기는 것을 본다 |

속도 일반화를 주 기준으로 삼으려면 `cv_S` 가 2 fold 라 부족하다. 누적 외삽 규칙을 유지한 채
fold 를 늘리려면 `00_folds.py` 에 **새 역할 컬럼으로 추가**해야 한다 — 기존 `folds_c.csv` 를 고치면
C 실험 결과의 재현성이 깨진다.
