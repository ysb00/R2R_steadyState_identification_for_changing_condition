# 1. 먼저 알아야 할 것

## 1.1 용어

| 용어 | 뜻 |
|---|---|
| **run** | 운전 조건 1개의 측정 1회. **조건당 run 이 1개뿐이라 run = 조건**이다. 총 210개, run 하나가 약 1,288 샘플(140 s) |
| **fold** | 교차검증 분할. 주 실험은 Film Tension 설정값 수준별 5-fold |
| **seed** | 난수 시드 반복 (0~4, 5회). GMM 초기화와 인코더 학습에 쓰인다 |
| **시점(timestep)** | 샘플 1개. 약 0.109 s 간격(≈9.17 Hz). **모든 판정과 지표는 시점 단위**다 |
| **e** | 분석 대상 신호. `e = Film Tension #1 − Film-Tension Setting Value` (실측 장력 − 설정값, kg) |
| **트랙 A** | 라벨을 쓰지 않는 평가 경로. 표현 → 표준화 → 2-군집 GMM → \|e 평균\| 작은 군집을 steady 로 지정 → 판정 |

## 1.2 fold 가 뜻하는 것 — "Fold 1: film tension 3 kg" 의 의미

**3 kg 를 검증(test)에 쓴 fold 라는 뜻이다.** 즉 장력 3 kg 조건의 run 42개는 학습에 전혀 쓰이지 않고,
나머지 4수준(4·5·6·7 kg)의 168 run 으로만 학습한 뒤 3 kg 에서 평가한다.

| fold | 검증(test)에 쓴 Film Tension | 학습에 쓴 Film Tension | 검증/학습 run | 성격 |
|---|---|---|---|---|
| **1** | **3 kg** | 4, 5, 6, 7 kg | 42 / 168 | **외삽** (격자 끝) |
| 2 | 4 kg | 3, 5, 6, 7 kg | 42 / 168 | 내삽 |
| 3 | 5 kg | 3, 4, 6, 7 kg | 42 / 168 | 내삽 |
| 4 | 6 kg | 3, 4, 5, 7 kg | 42 / 168 | 내삽 |
| **5** | **7 kg** | 3, 4, 5, 6 kg | 42 / 168 | **외삽** (격자 끝) |

이 분할은 "**미학습 운전조건에서 쓸 수 있는가**"를 보기 위한 것이다(`research_plan.md` 0절·6절).
fold 1 과 5 는 학습 범위 밖을 예측해야 하므로 **내삽 fold 보다 나쁜 것이 정상이고, 그래야 설계가 의도대로 작동한다는 신호**다.

> 분할은 run 단위가 아니라 **설정값 수준 단위**다. run 단위로 나누면 검증 조건과 비슷한 조건이
> 학습에 들어가 "미학습 조건" 이 아니게 된다.

## 1.3 클래스 비율 — 모든 지표의 기준선

| 라벨 (`Trigger 4`) | 뜻 | 비율 |
|---|---|---|
| 1 | steady state | 85.8% |
| 0 | 미안정 (non-steady) | 7.6% |
| 2 | ambiguous | 6.6% |

ambiguous 는 지표 계산에서 **제외**한다. 따라서 채점 대상 중 non-steady 는 **8.13%** 다.

**이 비율 때문에 아무 정보 없는 자명해도 좋아 보이는 숫자를 낸다:**

| 자명해 | 오염률 | 보존률 | Prec(ns) | Rec(ns) |
|---|---|---|---|---|
| "모든 시점을 steady 로 선언" | **0.081** | **1.000** | — | 0.000 |

즉 **오염률 0.081 / 보존률 1.000 은 "정보 0" 의 성적**이고, `Prec(ns) = 0.081` 도 마찬가지다.
어떤 방법을 평가할 때 반드시 이 값과 비교해야 한다.

# 2. 핵심 지표 2개 — 정의와 해석

이 연구의 목적은 **하류 작업(이상탐지·품질 모델 학습)에 쓸 steady 데이터를 라벨 없이 골라내는 것**이다.
그래서 지표도 "골라낸 데이터의 품질" 과 "골라낸 양" 두 축으로 본다.

혼동행렬을 먼저 정의한다. 시점 t 에 대해:

| | 실제 steady | 실제 non-steady |
|---|---|---|
| **steady 로 판정** | TP (맞게 골랐다) | **FP (불량을 골랐다)** |
| **non-steady 로 판정** | FN (쓸 데이터를 버렸다) | TN (맞게 버렸다) |

## 2.1 오염률 (`contamination_rate`) — 최우선 지표

```
오염률 = FP / (TP + FP)
       = (steady 로 판정한 시점 중 실제로는 non-steady 인 시점) / (steady 로 판정한 전체 시점)
       = 1 − Precision(steady)
```

**정의**: 골라낸 steady 데이터 중 **불순물의 비율**.

**해석**: 이 값이 0.05 라면, 선별한 데이터의 5% 가 실제로는 불안정 구간이다. 그 데이터로 이상탐지 모델을
학습시키면 **모델이 "불안정" 을 정상으로 배우게 된다.** 그래서 계획 문서에서 최우선 지표로 지정했다
(`research_experiments_plan.md` 5절).

**클수록**: 선별 결과를 신뢰할 수 없다. 1.000 이면 골라낸 것이 **전부** non-steady 라는 뜻이다.

**반드시 함께 봐야 하는 이유**: 분모가 "steady 로 판정한 양" 이다. 따라서 **steady 를 거의 선언하지 않으면
오염률은 자동으로 낮아진다.** 극단적으로 steady 를 1개 시점만 선언하고 그게 맞으면 오염률 0.000 이다.
**오염률 단독으로는 방법을 평가할 수 없다.**

## 2.2 보존률 (`retention_rate`)

```
보존률 = TP / (TP + FN)
       = (steady 로 판정한 시점 중 실제 steady) / (실제 steady 인 전체 시점)
       = Recall(steady)
```

**정의**: 실제 쓸 수 있는 steady 데이터 중 **살려낸 비율**. `1 − 보존률` 이 버린 비율이다.

**해석**: 0.70 이면 쓸 수 있는 데이터의 30% 를 버렸다는 뜻이다. 데이터가 아깝지만 오염률이 낮으면
"보수적이지만 안전한" 선별이다. 반대로 1.000 에 가까우면서 오염률이 높으면 "아무거나 다 가져온" 것이다.

**클수록**: 데이터를 많이 살렸다. 단 오염률과 함께 봐야 한다.

## 2.3 두 지표를 함께 읽기 — 4분면

**두 지표는 상충한다.** steady 판정을 늘리면 보존률이 오르고 오염률도 오른다. 그래서 조합으로 읽는다.

| | 오염률 낮음 | 오염률 높음 |
|---|---|---|
| **보존률 높음** | ✅ **이상적** — 많이 살리고 깨끗하다 | ⚠️ **과도 관대** — 가려내지 못했다. "전부 steady" 자명해가 여기(0.081 / 1.000) |
| **보존률 낮음** | ⚠️ **과도 보수** — 깨끗하지만 데이터를 많이 버렸다 | ❌ **완전 실패** — 적게 살리고 그마저 더럽다 |

현재 결과를 이 틀에 넣으면:

| 방법 | 오염률 | 보존률 | 분류 |
|---|---|---|---|
| **CoST (W=160)** | 0.003 | 0.987 | ✅ **이상적** — 98.7% 를 살리면서 불순물 0.3% |
| MovStd-Slope (고정창) | 0.033 | 0.978 | ✅ 이상적에 가깝다 (불순물 3.3%) |
| CoST (W=256) | 0.001 | 0.926 | ✅ 양호 |
| CoST (W=512) | 0.000 | 0.707 | ⚠️ 과도 보수 — 29% 폐기 |
| TS2Vec | 0.002 | 0.707 | ⚠️ 과도 보수 — 29% 폐기 |
| SoftCLT-fs / -ref | 0.001 | 0.639 / 0.624 | ⚠️ 과도 보수 — 36~38% 폐기 |
| MOMENT | 0.030 | 0.625 | ⚠️ 과도 보수 — 37% 폐기 |
| R-test (1/10 다운샘플) | 0.021 | **0.174** | ⚠️ 극단적 보수 — **83% 폐기**, 쓸 수 없다 |
| R-test (9 Hz) | **1.000** | **0.000** | ❌ **완전 실패** |

**여기서 바로 읽히는 것:**

1. **"오염률이 낮다" 는 칭찬이 아니다.** TS2Vec(0.002)·SoftCLT(0.001)·CoST-W512(0.000)가 오염률은 CoST-W160(0.003)보다 **낮은데** 보존률이 0.62~0.71 이다. steady 를 적게 선언해서 분모가 작아진 결과다.
2. **구분이 되는 지점은 보존률이다.** 오염률은 대부분 0.00~0.03 범위에 모여 있고, 보존률이 0.00~0.99 로 벌어진다.
3. **R-test 는 두 버전 모두 실무적으로 쓸 수 없다.** 9 Hz 판은 완전 실패(오염률 1.000), 다운샘플판은 전제를 맞춰줘도 83% 를 버린다.

## 2.4 non-steady 쪽 지표 — 왜 따로 보는가

오염률·보존률은 **steady 를 positive 로 본** 지표다. 반대 방향도 기록한다.

```
Precision(ns) = TN / (TN + FN)   non-steady 로 판정한 시점 중 실제 non-steady 비율
Recall(ns)    = TN / (TN + FP)   실제 non-steady 중 non-steady 로 판정한 비율
F1(ns)        = 두 값의 조화평균
```

**`Precision(ns)` 를 기준선 0.081 과 비교하는 것이 가장 변별력이 높다.** 0.081 이면 "정보 0" 이다.

| 방법 | Prec(ns) | 기준선(0.081) 대비 | 해석 |
|---|---|---|---|
| R-test (9 Hz) | **0.081** | **1.0배** | 정보가 전혀 없다. "전부 non-steady" 자명해와 수학적으로 동일 |
| R-test (다운샘플) | 0.092 | 1.1배 | 거의 없다 |
| MOMENT | 0.157 | 1.9배 | 매우 낮다 |
| CoST (W=512) | 0.231 | 2.8배 | |
| SoftCLT-fs / -ref | 0.248 / 0.275 | 3.1 / 3.4배 | |
| TS2Vec | 0.344 | 4.2배 | |
| CoST (W=306) | 0.430 | 5.3배 | |
| CoST (W=256) | 0.537 | 6.6배 | |
| MovStd-Slope (고정창) | 0.715 | 8.8배 | |
| **CoST (W=160)** | **0.844** | **10.4배** | 유일하게 실용 수준 |

**AUROC 와 어긋나는 지점이 중요하다.** R-test 다운샘플판은 AUROC 0.901 로 MovStd-Slope(0.884)보다
높은데 `Prec(ns)` 는 0.092 대 0.715 다. 이것은 **"순위는 잘 매기는데 임계값이 틀렸다"** 는 뜻이고,
`research_plan.md` 2절의 연구 동기("통계 기반 SSI 는 조건별 임계값 재튜닝이 필요하다")를
본 데이터에서 직접 보여주는 결과다.

## 2.5 AUROC / AUPRC

판정(임계값)과 무관하게 **점수의 순위 품질**만 본다. 점수는 GMM 의 non-steady 사후확률
(= 1 − steady 군집 사후확률)이고, R-test 는 R 통계량 자체다.

| 지표 | 뜻 | 기준선 |
|---|---|---|
| `auroc` | 무작위로 뽑은 non-steady 시점의 점수가 steady 시점보다 높을 확률 | 0.5 (무작위) |
| `auprc` | precision-recall 곡선 아래 면적. 소수 클래스에서 AUROC 보다 변별력이 높다 | **0.081** (= non-steady 비율) |

AUPRC 는 기준선이 0.5 가 아니라 **0.081** 이다. MOMENT 의 AUPRC 0.143 은 기준선의 1.8배로 매우 낮다.

## 2.6 steady 진입 시점 오차

`research_plan.md` 3.1 D6 의 "시점 단위 정상 진입 시점 검출" 평가다.

```
진입 오차(s) = (방법이 판정한 진입 시점 − Trigger 4 의 첫 steady 시점) × 0.109
```

방법의 진입 시점은 **연속 10개 시점이 steady 로 판정된 첫 시점**이다(`ENTRY_MIN_CONSEC = 10`, 깜빡임 방지).

| 부호 | 뜻 | 실무 영향 |
|---|---|---|
| **음수** | 전문가보다 **빨리** steady 선언 (성급) | 과도구간을 steady 데이터에 포함시킬 위험 |
| **양수** | 전문가보다 **늦게** steady 선언 (보수) | 쓸 수 있는 초기 steady 구간을 버린다 |

`runmean_entry_err_s` 는 부호 포함 평균(= bias, 방향), `runmae_entry_err_s` 는 절댓값 평균(= 정확도).
**bias 가 0 에 가까워도 MAE 가 크면** run 마다 빠르고 늦음이 섞여 있다는 뜻이다.

현재 결과:

| 방법 | bias (s) | MAE (s) | 해석 |
|---|---|---|---|
| **CoST (W=160)** | **−1.7** | **5.3** | 거의 정확. 전체 최고 |
| MovStd-Slope (고정창) | −10.9 | 11.3 | 11초 성급 |
| CoST (W=256) | +8.3 | 10.0 | 8초 보수 |
| MOMENT | −14.1 | 14.3 | 14초 성급 |
| TS2Vec | +30.1 | 31.6 | 30초 보수 |
| CoST (W=512) | +35.5 | 35.5 | 36초 보수 (창 길이 55.8 s 의 0.64배) |
| SoftCLT-fs / -ref | +39.6 / +44.8 | 40.7 / 45.6 | 40~46초 보수 |
| R-test (다운샘플) | +27.6 | 43.8 | bias 와 MAE 차이가 크다 = run 마다 들쭉날쭉 |

**CoST 의 진입 bias 가 창 길이에 비례해 커진다**(−1.7 → +8.3 → +13.6 → +35.5). causal 이동창이
과도구간을 창 길이만큼 "기억" 해서 steady 선언이 늦어지는 것이다. 창 길이 선택의 핵심 상충 관계다.

# 3. 탐색적 분석 (`outputs/02_eda/`) — 무엇을 했고 어떻게 읽는가

## 3.1 무엇을 왜 했나

**목적은 이동창 길이를 라벨 없이 정하는 것**이다. 창 길이는 통계 기준선·CoST·TS-TCC·SimMTM 에
모두 들어가는 값인데, 처음에는 **임의로 64 샘플**을 썼다. 그 값이 결과를 좌우한다는 것이 드러나
(CoST 창 160→512 에서 AUPRC 0.814→0.231) 근거 있는 값이 필요해졌다.

근거의 출발점은 **steady 구간에도 주기 외란이 남아 있다**는 사실이다. 창이 그 주기보다 짧으면
진동이 "추세" 로 보여 steady 를 비정상으로 오판한다. 그래서 **주기를 측정해 창 길이를 유도**한다.

측정은 **라벨 없이** 해야 한다. 기존 `research_plan.md` 1.2절 수치는 "run별 steady 앞 1024 샘플"
에서 측정한 것이라 `Trigger 4` 가 개입했다. 본 분석은 **run 전체 신호**를 쓴다.

구현: `code/02_eda/01_rotation_frequency.py` (원본 zip 에서 직접 읽어 재현 가능)
상세 해설과 결론: **`docs/periodic_disturbance.md`**

## 3.2 `01_rotation_frequency.csv` — 15개 컬럼 전부

1행 = run 1개 (210행).

| 컬럼 | 의미 | 단위 | 읽는 법 |
|---|---|---|---|
| `run_id` | run 식별자 `T<장력>_R<리와인더장력>_V<속도>` | — | |
| `T`, `R`, `V` | 그 run 의 설정값 (파일명에서 파싱) | kg, kg, mm/s | |
| `n` | run 의 시점 수 | 샘플 | 1,275~1,300. **주파수 해상도 `fs/n` 를 정한다** (약 0.0072 Hz) |
| **`f_peak_Hz`** | run 전체 스펙트럼에서 0.03–0.30 Hz 범위의 **최대 파워 주파수** | Hz | **회전 1차 성분 추정치.** 속도에 비례해야 가설이 맞다 |
| `period_s` | `1 / f_peak` | 초 | 외란이 한 번 반복되는 시간 |
| **`period_samples`** | `fs / f_peak` | 샘플 | **창 길이의 하한.** 창이 이보다 짧으면 1주기를 못 담는다 |

## 3.4 결론과 그 함의

**① 주기 외란의 출처는 리와인더 롤이 아니라 지름 ≈ 249 mm 의 고정 지름 회전체다** (그림 2·3).
어느 롤러인지는 장비 도면이 있어야 특정되지만, **창 길이 유도에는 영향이 없다** — 필요한 것은
둘레 값 하나이고 그것이 측정됐다.

**② 창 길이 = 144 샘플 (15.7 s), 불확실성 ±8.**

```
C = 783.5 mm → f_min = 50/783.5 = 0.0638 Hz → W = ⌈9.174/0.0638⌉ = 144
```

하한은 "1주기를 담아야 한다"(그림 4), 상한 방향은 "길면 진입이 늦어진다"(그림 5)가 정한다.
**하한에서 멈춘 값**이다.

**③ `Rewinder roll diameter` 열은 모델 입력에 넣지 않는다.** 외란 출처가 아니고(①),
설정값으로 거의 설명되지 않으며(R² = 0.144) run 안에서 자라는 **수집 순서 교란**이다. 지름이
run 마다 거의 고유해서 모델에 주면 **run 식별 지름길**이 된다. 창 길이를 찾는 **진단에만** 썼다.

**④ 창 길이 교체의 실제 효과 (MovStd-Slope 실측).** 창을 64 → 144 로 바꾼 결과:

| 지표 | W=64 | W=144 | 변화 |
|---|---|---|---|
| **V=50 오염률** | **0.083** | **0.028** | **3배 개선** |
| V=100 오염률 | 0.043 | 0.003 | 14배 개선 |
| V≥150 오염률 | 0.016–0.017 | 0.000 | |
| 진입 bias (s) | −10.9 | **+2.5** | 0 에 훨씬 가까워짐 |
| AUROC | 0.884 | **0.957** | 개선 |
| Prec(ns) | **0.715** | 0.453 | **악화** |
| AUPRC | **0.718** | 0.608 | **악화** |

**창 규칙이 고치려던 것(저속 오염·진입 편향)은 실제로 고쳤다** — D1 가설의 직접적 확인이다.
다만 `Rec(ns)` 가 0.614 → 0.911 로 올라가면서 non-steady 를 더 공격적으로 선언하게 되어
`Prec(ns)`·AUPRC 는 떨어졌다. **일률적 개선이 아니라 운용점의 이동**이다.

> 속도별 창 변형은 거의 변화가 없다(`Prec(ns)` 0.653 → 0.648). 기존 값이 이미 규칙 1b 의
> 약 1.11배였기 때문이다 — 바꿀 것이 거의 없었다.

# 6. `_fold_metrics.csv` — 공통 30개 + 방법별 추가

## 5.1 접두사의 뜻 — `pooled_` / `runmean_` / `runstd_` / `n_runs_`

이것이 이 파일에서 가장 혼동되는 부분이다.

| 접두사 | 계산 방식 | 뜻 |
|---|---|---|
| **`pooled_`** | fold 안의 **모든 run 의 모든 시점을 한 덩어리로 합쳐** 지표를 한 번 계산 | **시점 가중 평균.** 시점이 많은 run, non-steady 가 많은 run 이 더 큰 영향을 준다. "이 fold 의 데이터 전체를 선별했을 때" 의 성적 |
| **`runmean_`** | run 별로 지표를 계산한 뒤 **산술평균** | **run(=조건) 가중 평균.** 42개 조건이 동등하게 기여한다. "조건마다 얼마나 잘하나" 의 평균 |
| **`runstd_`** | run 별 지표의 **표준편차** | **조건 간 변동성.** 크면 조건에 따라 성능이 들쭉날쭉하다는 뜻 |
| **`n_runs_`** | 그 지표가 **정의된 run 의 개수** | 42 보다 작으면 일부 run 에서 계산 불가. 예: non-steady 가 0개인 run 은 `n_runs_auprc` 에서 빠진다 |

**두 집계가 갈리는 것 자체가 정보다.** 실제 예 — R-test 다운샘플판:

| 지표 | pooled | runmean | 왜 갈리는가 |
|---|---|---|---|
| `precision_steady` | 0.979 | **0.756** | steady 로 판정한 시점이 run 당 몇 개뿐이라 run 단위 분모가 극히 작다. 한 run 에서 2개 중 1개가 틀리면 그 run 의 precision 은 0.5 이고, run 평균이 크게 끌려 내려간다 |
| `auprc` | 0.579 | **0.730** | 반대로 올라간다. non-steady 가 적은 run 에서 AUPRC 가 높게 나오고, run 평균은 그 run 들을 동등하게 세기 때문 |

**어느 것을 논문에 쓸까**: 오염률은 "데이터 전체의 불순물 비율" 이 실무적 의미이므로 `pooled_` 가 자연스럽고,
"조건마다 쓸 수 있나" 를 보려면 `runmean_` 이 맞다. 계획 문서는 **둘 다 기록**하기로 했다
(`worklog.md` 2026-10-22 §2 결정 4).

| `tau_inst` | SoftCLT | 인스턴스 축 soft label 날카로움. run 간 DTW 거리 d 에 대해 가중치 `w = 1/(1+exp(tau_inst·d))` | `SoftCLT-fs` 는 fold 마다 다르다(158~232), `SoftCLT-ref` 는 5.0 고정 |
| `tau_temp` | SoftCLT | 시간 축 soft label. 시점 차 Δt 에 대해 `w = 2/(1+exp(tau_temp·|Δt|))` | fs 0.034, ref 1.0 |
| **`n_eff_median`** | SoftCLT | **앵커당 유효 양성 수의 중앙값** = 비대각 가중치 합의 중앙값. 학습 run 167개 중 "실질적으로 몇 개가 양성 취급되는가" | **퇴화 진단용.** 0 에 가까우면 모든 쌍이 hard 음성(= TS2Vec 과 동일), 167 에 가까우면 음성이 사라진다. fs 는 5.0(목표값), ref 는 **75.5(퇴화)** |
| `n_eff_min`, `n_eff_max` | SoftCLT | 같은 양의 최솟값·최댓값 (앵커 167개에 대해) | 중앙값과 크게 다르면 앵커마다 양성 수가 불균등하다는 뜻 |
| `fit_sec` | TS2Vec, CoST, SoftCLT | 인코더 자기지도 학습 시간 (초) | 다른 작업과 동시 실행 시 늘어난다 |
| `total_sec` | 학습 있는 방법 + MOMENT | 학습 + 표현 추출 + GMM + 채점 전체 시간 (초) | |
| `n_epochs` | 학습 있는 방법 | 완료한 epoch 수 | 반복수 상한에 걸려 끊긴 마지막 epoch 은 세지 않는다 |
| `n_iters` | 학습 있는 방법 | 총 iteration 수 (600) | |
| `iters_per_epoch` | CoST, SoftCLT | 1 epoch 의 iteration 수 | **CoST 기존 결과의 이 값은 틀렸다** — `n_iters // n_epochs` 로 계산해 과대평가(600/3 → 200). 참값은 창별 **168/105/84/42**. SoftCLT 의 21 은 우연히 참값과 같다 |
| `data_passes`, `samples_seen` | 코드 수정 이후 실행분 | 학습 데이터 통과 횟수 / 본 시점 수 | **방법·창 간 학습량 비교에 쓴다.** 현재 CoST·SoftCLT 결과에는 없다(실행 후 추가) |
| `epoch_mean_loss_last` | CoST, SoftCLT | 마지막 완료 epoch 의 평균 손실 | |
| `final_loss` | 학습 있는 방법 | 마지막 20 iteration 의 평균 손실 (TS2Vec 은 마지막 epoch 평균) | `epoch_mean_loss_last` 보다 낮게 나온다 — epoch 평균은 epoch 초반의 큰 손실을 포함하기 때문 |
| **`steady_cluster`** | GMM 후단을 쓰는 방법 | 2군집 중 **steady 로 지정된 군집 번호** (0 또는 1) | **seed 마다 0/1 이 뒤바뀌는 것은 정상이다.** 군집 번호는 GMM 초기화에 따라 임의로 붙고, 어느 쪽이 steady 인지는 `e_mean` 으로 판단한다 |
| **`e_mean_c0`, `e_mean_c1`** | GMM 후단을 쓰는 방법 | 군집 0·1 에 속한 학습 fold 시점들의 **e 평균 (kg)** | **절댓값이 작은 쪽이 steady 로 지정된다.** 예: `(-0.002, -0.081)` 이면 군집 0 이 steady. **두 값이 비슷하면 군집이 steady 와 무관하게 갈렸다는 경고 신호**다 |

| 방법 | 보존률 fold간 σ | 보존률 seed간 σ | 해석 |
|---|---|---|---|

4. run 단위로 `k`(시점 순번) 오름차순 정렬한다.

## 10.2 방법 1 — R-test (Cao & Rhinehart, 1995)

**아이디어**: 같은 분산을 두 가지 방법으로 추정해 비교한다. 정상상태면 두 추정이 같아 비율이 1 에 가깝고,
과도상태면 필터값이 실제 신호를 뒤따라가지 못해 한쪽 추정이 부풀어 비율이 1 보다 훨씬 커진다.

식과 기본값 출처: Rhinehart, "Automated Steady and Transient State Identification in Noisy Processes"
(r3eda 튜토리얼, 2019-05-08) pp.12-16.

### 10.2.1 R 통계량 계산 (`rtest_statistic`) — run 1개에 대해

필터값 3개(`xf`, `nu2f`, `delta2f`)와 직전 데이터(`x_old`)를 **모두 0 으로 초기화**한 뒤,
시점 i = 0, 1, 2, … 순서로 다음을 반복한다.

```
① nu2f    ← λ2 · (x[i] − xf)²        + (1 − λ2) · nu2f        # 데이터와 '직전' 필터값의 차이 제곱
② xf      ← λ1 · x[i]                + (1 − λ1) · xf          # 신호 EWMA (①보다 나중에 갱신)
③ delta2f ← λ3 · (x[i] − x_old)²     + (1 − λ3) · delta2f     # 연속 차분 제곱
④ x_old   ← x[i]
⑤ R[i]    = (2 − λ1) · nu2f / delta2f
```

- `λ1 = 0.2`, `λ2 = λ3 = 0.1` (원 논문 권장값)
- **①을 ②보다 먼저 하는 것이 중요하다.** `xf` 를 갱신하기 전의(= 직전) 값을 쓰는 것이 원 논문 식이고, 이렇게 해야 자기상관으로 인한 편향이 줄어든다.
- `delta2f` 가 0 이 되는 시점(연속 변화가 전혀 없는 구간)은 R 이 무한대가 되므로, **그 run 의 유한한 최댓값으로 바꾼다.** 원 논문도 무잡음 구간에서 식이 깨진다고 명시한다.
- 필터 초기화 영향이 약 **35 샘플**(3.5/λ1) 남는다.

### 10.2.2 판정 (`rtest_decide`) — 2-임계값 히스테리시스

초기 상태를 **non-steady** 로 두고 시점 순서로:

```
R[i] > 2.5  →  non-steady (0)
R[i] < 0.9  →  steady (1)
그 사이     →  직전 판정을 유지
```

- 임계값 `2.5` / `0.9` 는 원 논문 기본값이다.
- 두 임계값 사이에서 직전 판정을 유지하는 것이 히스테리시스이고, 경계에서 깜빡이는 것을 막는다.
- 초기 상태를 non-steady 로 두는 것은 필터 초기화 구간에서 R 이 높게 나오는 것과 일치한다.

### 10.2.3 다운샘플링 변형 (`R-test-decimated`)

**왜 필요한가**: 원 논문은 "정상상태 잡음에 자기상관이 없도록 **샘플링 간격을 고른다**" 를 전제한다.
본 데이터는 9 Hz 에서 steady 구간 lag1 자기상관이 0.85 라 전제가 깨진다. lag10 에서 0.16 까지
떨어지는 것을 근거로 10배 다운샘플링한다(`RTEST_DECIMATE = 10`, 임의로 정한 값).

```
① e 를 10 샘플마다 하나씩 뽑는다:  e[::10]
② 그 신호로 R 통계량과 판정을 계산한다 (위와 동일한 함수)
③ 판정을 원래 시점으로 되돌린다:  back = arange(len(e)) // 10
   -> 시점 i 는 '직전 다운샘플 시점'의 판정을 그대로 가져온다 (causal forward-fill)
④ 채점은 모든 방법과 같은 9 Hz 시점에서 한다
```

③이 causal 인 것이 중요하다 — 미래 시점의 판정을 끌어오지 않는다.

### 10.2.4 점수와 학습

- **non-steady 점수 = R 통계량 자체**(클수록 과도상태). AUROC·AUPRC 에 이 값을 쓴다.
- **학습이 없다.** 원 논문 임계값을 그대로 쓰므로 학습 fold 를 사용하지 않고, 검증 fold 에서 채점만 한다.
- 결정론적이라 seed 반복을 1회만 한다.

### 10.2.5 실행 중 함께 출력하는 전제 확인값

다운샘플링이 실제로 자기상관을 줄였는지 확인하기 위해, 두 버전에 대해 **lag1 자기상관 run 평균**,
**R 중앙값**, **steady 임계값(0.9) 미만 비율**, **TS 임계값(2.5) 초과 비율**을 출력한다.
실측: 9 Hz 에서 R 중앙값 3.77 / R>2.5 비율 0.881 / R<0.9 비율 0.000 → 1/10 다운샘플링 후
R 중앙값 **1.43** / R>2.5 비율 0.167 로 바뀐다(정상상태 기대값은 R ≈ 1).

## 10.3 방법 2 — 이동창 표준편차 + 기울기 (`MovStd-Slope`)

**아이디어**: "조용하고(변동이 작고) 흐르지 않으면(추세가 없으면) 정상상태" 라는 정의를 그대로 옮긴다.
원 논문은 없는 단순 기준선이다.

### 10.3.1 특징 계산 (`rolling_std_slope`) — run 1개, 창 길이 w

```
① 표준편차:  길이 w 의 뒤쪽(causal) 이동창에서 e 의 표본표준편차        [kg]
② 기울기:    같은 창에서 최소제곱 직선의 기울기                          [kg/s]
             가중치 kern = j / Σj²  / DT,  j = (0..w-1) − (w-1)/2
             (중심화한 시간 인덱스를 쓰면 최소제곱 기울기가 내적 한 번으로 계산된다)
③ 창이 다 차지 않은 앞 w−1 개 시점은 '첫 완전창' 의 값으로 채운다
```

- **①②는 causal** 이다 — 시점 i 의 값은 `e[i−w+1 .. i]` 만 쓴다. 미래를 보지 않는다.
- ③의 이유: 창 길이가 달라도 **채점 대상 시점 수가 같아야** 변형 간 비교가 공정하다. 앞부분을 버리면 창이 긴 변형이 더 적은 시점에서 채점된다.
- `DT = 0.109` 로 나눠 기울기 단위를 kg/sample → **kg/s** 로 바꾼다.

### 10.3.2 두 변형

| 변형 | 창 길이 | 근거 |
|---|---|---|
| `MovStd-Slope-fixed` | **64 samples** (약 7.0 s) 고정 | 임의로 정한 값 |
| `MovStd-Slope-speed` | **`W(V) = round(64 × 125 / V)`** — 속도에 반비례 | steady 구간 주기 성분의 주파수가 속도에 비례한다는 관찰(`research_plan.md` 1.2절). 필름 이동 거리 기준 창과 같은 형태(∝1/V) |

속도별 창의 실제 길이:

| V (mm/s) | 50 | 75 | 100 | 125 | 150 | 175 | 200 |
|---|---|---|---|---|---|---|---|
| 창 길이 (samples) | 160 | 107 | 80 | **64** | 53 | 46 | 40 |
| 창 길이 (s) | 17.4 | 11.7 | 8.7 | 7.0 | 5.8 | 5.0 | 4.4 |

`SPEED_REF = 125` 는 조건 격자의 중앙값이고, 그 속도에서 고정창과 같아진다.

### 10.3.3 임계값을 손으로 정하지 않는 이유와 그 방법

"std 가 0.05 kg 미만이고 |기울기| 가 0.01 kg/s 미만이면 steady" 같은 임계값을 손으로 정하면
**라벨을 보고 조정하게 되거나(전제 위반), 조건마다 다시 맞춰야 한다**(연구 동기와 모순).

그래서 **(std, |기울기|) 2차원을 하나의 "표현" 으로 보고, 다른 모든 비교군과 완전히 같은 트랙 A 후단에
넣는다.** 즉 이 방법은 "2차원 표현을 만드는 인코더" 로 취급된다.

```
① z = [std, |slope|]                     기울기는 부호를 버리고 크기만 쓴다
                                          (오르는 추세와 내리는 추세를 같은 '비정상' 으로 본다)
② 학습 fold 의 z 로 표준화(StandardScaler) 적합
③ 같은 데이터로 2-군집 GMM(diag 공분산) 적합
④ 군집별 e 평균을 계산해 |e 평균| 이 작은 군집을 steady 로 지정
⑤ 검증 fold 의 z 에 ②③을 그대로 적용 -> steady 군집 사후확률
⑥ 사후확률 >= 0.5 이면 steady 로 판정, non-steady 점수 = 1 − 사후확률
```

②의 표준화가 **필수**다. std 는 kg 단위(0.04 수준), 기울기는 kg/s 단위로 분산 규모가 달라서,
표준화 없이 GMM 을 적합하면 분산이 큰 축이 군집을 지배한다.

④가 **라벨을 쓰지 않는 steady 군집 지정 규칙**이다. "정상상태는 설정값을 추종한다(e ≈ 0)" 는
도메인 정의를 쓴 것이고, 라벨이 아니다.

### 10.3.4 학습·평가 단위

fold 5개 × seed 5개 = 25회. 각 회에서 ②③④를 학습 fold(168 run 의 모든 시점)로 적합하고
검증 fold(42 run)에 적용한다. 표현 계산(①)은 fold 와 무관하므로 run 단위로 한 번만 한다.

# 13. SoftCLT 두 변형(`-fs` / `-ref`)의 차이와 결론

## 12.1 SoftCLT 가 무엇을 하는 방법인가

TS2Vec 의 대조학습은 "양성 1개, 나머지 전부 음성" 이라는 **hard 라벨**을 쓴다. 두 축에서:

- **인스턴스 축**: 같은 시점에서 같은 run 의 두 view = 양성, **다른 run** = 음성
- **시간 축**: 같은 run 에서 같은 시점의 두 view = 양성, **다른 시점** = 음성

본 데이터에서는 이것이 틀린 경우가 많다. `T5_R4_V100` 과 `T5_R4_V125` 는 설정이 한 칸 차이라
신호가 거의 같은데 hard 음성으로 밀어낸다. 시점 t 와 t+1 은 0.109 s 차이로 거의 확실히 같은 상태인데
hard 음성이다. **이것이 거짓 음성 문제**(`research_plan.md` G3)이고, SoftCLT 가 노린 것이다.

SoftCLT 는 음성에 **0~1 연속 가중치**를 준다. 가까운 것은 "약한 양성" 으로 취급한다.

| 파라미터 | 담당 축 | "가깝다" 의 척도 | 가중치 식 |
|---|---|---|---|
| `tau_inst` | 인스턴스 (run ↔ run) | run 간 **DTW 거리** d (MinMax 로 [0,1] 정규화) | `w = 1/(1+exp(tau_inst·d))` |
| `tau_temp` | 시간 (시점 ↔ 시점) | 시점 차 `|Δt|` (샘플) | `w = 2/(1+exp(tau_temp·|Δt|))` |

**tau 는 0 과 ∞ 양쪽에서 TS2Vec 으로 퇴화한다.** 0 이면 코드가 soft 요소를 끄고(`soft_instance = tau > 0`),
∞ 면 모든 가중치가 0 이 되어 hard 음성이 된다. **중간 구간을 써야 한다.**

## 12.2 두 변형의 차이

| | `SoftCLT-ref` | `SoftCLT-fs` |
|---|---|---|
| 뜻 | **저장소/저자 설정 그대로** | **본 데이터에서 유도** |
| `tau_inst` | **5.0** — 저자가 제공하는 UCR 128개 데이터셋 튜닝표의 중앙값 | **fold 마다 수치해로 구함** (157.6 / 190.3 / 216.6 / 232.0 / 204.1) |
| `tau_inst` 결정 근거 | 저자 표 중앙값 | **앵커당 유효 양성 수(`n_eff`) 중앙값이 5 가 되도록.** 목표값 5 는 조건 격자에서 나온다 — 각 축 ±1 이 인접 조건이므로 학습 fold 에서 인접 run 이 4~6개 |
| `tau_temp` | **1.0** — 저자 표 중앙값. 가중치 절반 반경 **1 샘플(0.11 s)** | **0.034** — `ln3/r`, r = 32 샘플(3.5 s) = MovStd-Slope 창 64 의 절반 |
| 결과 `n_eff` | **75.5** (학습 167 run 중) | **5.0** (목표 달성) |
| 다른 설정 | 완전히 동일 (ALPHA 0.5, LAMBDA 0.5, DTW, batch 8, lr 0.001, 320차원, 600 iter) | 동일 |

**왜 `-fs` 를 만들었는가**: 저자 표의 `tau_inst` 격자(0.1 ~ 40)가 **본 데이터에서 전부 퇴화**한다.
DTW 거리를 MinMax 로 정규화하는데, 다른 모든 run 과 현격히 먼 run 2개
(`T3_R2_V200`, `T4_R6_V150` — e 범위가 −2.06 ~ +2.87 kg 로 전형적 run 의 ±0.25 를 크게 벗어난다)가
최대값을 지배해 **나머지 99% 가 [0, 0.05] 로 짓눌린다**(정규화 거리 중앙값 0.021~0.028).
그 결과 `n_eff` 가 tau_inst=5 에서 75.5, 격자 최대 40 에서도 58~64 다 — 학습 run 167개 중
58~82개가 "절반쯤 양성" 이 되어 **음성이 사실상 사라진다.** 비퇴화에는 tau_inst 가 158~232 이 필요하다
(격자 최대의 4~6배).

## 12.3 결과와 결론

| 지표 | `SoftCLT-ref` | `SoftCLT-fs` | (참고) TS2Vec |
|---|---|---|---|
| `n_eff` | 75.5 (퇴화) | **5.0** (정상) | — |
| 오염률 | 0.001 | 0.001 | 0.002 |
| 보존률 | 0.624 | 0.639 | 0.707 |
| Prec(ns) | **0.275** | **0.248** | **0.344** |
| Rec(ns) | 0.990 | 0.985 | 0.988 |
| F1(ns) | 0.401 | 0.381 | 0.474 |
| AUROC | 0.807 | 0.812 | 0.849 |
| AUPRC | **0.273** | **0.244** | **0.344** |
| 진입 bias / MAE (s) | +44.8 / 45.6 | +39.6 / 40.7 | +30.1 / 31.6 |
| 보존률 seed간 σ | **0.304** | 0.212 | 0.217 |

### 결론 3가지

**① tau 가 성능 문제의 원인이 아니었다.** `n_eff` 를 75.5 → 5.0 으로 **15배** 줄여 퇴화를
해소했는데도 성능이 개선되지 않았다(AUPRC 0.273 → 0.244, 오히려 소폭 하락). 즉 "저자 격자가
본 데이터에서 퇴화한다" 는 진단은 사실이지만, **그것을 고쳐도 결과가 바뀌지 않으므로 성능 문제의
원인은 다른 데 있다.**

**② soft label 을 추가하는 것 자체가 본 데이터에서 역효과다.** 두 변형 모두 평범한
TS2Vec(Prec(ns) 0.344, AUPRC 0.344)보다 **나쁘다.** SoftCLT 는 TS2Vec 에 soft label 만 더한
방법이고 나머지 설정이 동일하므로, 이 차이는 soft label 때문이다. 거짓 음성 완화가 목표인데
**steady 가 86% 인 데이터에서 "가까운 것을 양성으로" 하면 steady/non-steady 경계까지 뭉개는** 것으로 보인다.
`Rec(ns)` 가 0.985~0.990 으로 non-steady 를 거의 다 잡으면서 `Prec(ns)` 가 0.25 수준인 패턴이 그 증거다.

**③ 두 변형 모두 "과도 거부" 형이다.** 보존률 0.62~0.64 로 **쓸 수 있는 steady 데이터의 36~38% 를
버린다.** 진입 시점도 40~46초 늦다. steady 데이터 선별이 목적인 본 과제에서는 쓸 수 없는 수준이다.

### 주의 — 아직 확정할 수 없는 것

600 iter 는 수렴 전이고, TS2Vec 에서 **학습이 덜 된 쪽이 모든 지표에서 더 좋았다**
(최종손실↔AUPRC 상관 +0.61). SoftCLT 는 run 이 분할되지 않아 600 iter 에서 데이터를 **28.6회**
통과하는데 CoST W=160 은 **3.57회** 다. 따라서 "SoftCLT 가 CoST 보다 나쁘다" 를 설계 차이로
단정할 수 없다 — 학습량 차이가 섞여 있다(`hyperparameters.md` §11 문제 9).

# 15. 결과를 읽을 때의 주의 5가지

1. **"거의 전부 steady" 라는 자명해가 꽤 좋은 숫자를 낸다.** steady 가 86% 이므로 오염률 0.081 / 보존률 1.000 이 나온다. 오염률·보존률만 보고 판단하면 안 되고, `Prec(ns)` 를 기준선 **0.081** 과, AUPRC 를 기준선 **0.081** 과 비교해야 한다.
2. **오염률이 낮다고 좋은 게 아니다.** steady 로 인정하는 양 자체가 적으면 오염률은 자동으로 낮아진다. TS2Vec 이 오염률 0.002(전체 최저급)인데 AUPRC 0.344(하위)인 이유다. **반드시 보존률과 함께 읽는다**(§2.3 의 4분면).
3. **AUROC 가 높다고 쓸 수 있는 게 아니다.** R-test 다운샘플판은 AUROC 0.901 인데 `Prec(ns)` 0.092, 보존률 0.174 다. 순위는 매기지만 임계값이 틀렸다.
4. **현재 학습량(600 iter)이 수렴 전이다.** TS2Vec 에서 학습이 덜 된 쪽이 모든 지표에서 더 좋았다. 따라서 학습 있는 방법의 성능이 **설계 덕인지 미학습 덕인지 아직 구분되지 않는다.**
5. **CoST 창 길이 비교는 학습량과 교란되어 있다.** `max_train_length = W` 때문에 같은 600 iter 에서 데이터 통과 횟수가 창별로 3.57~14.29회로 4배 차이 난다. "창이 길면 나빠진다" 를 창 효과로 단정할 수 없다. 상세는 `hyperparameters.md` §11 문제 9.
