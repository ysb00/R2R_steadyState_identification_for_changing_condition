# Proposed (final v1) — Ablation: 무엇이 다르고, 효과가 어땠나

제안 방법은 baseline `CoST-W144-noscaleshift` 에 세 가지를 더한 것이다.
이 문서는 **각 구성 요소를 하나씩 넣어가며** 무엇이 달라지고 효과가 어땠는지를 정리한다.

$$\text{baseline} \;\xrightarrow{\;+\,\text{trunk 분리}\;}\;
\xrightarrow{\;+\,\text{차수 추적}\;}\;\xrightarrow{\;+\,\text{seasonal 동결}\;}\;
\textbf{Proposed (final v1)}$$

- 수치 출처: `outputs/07_proposed_final_v1/table2_ablation_study_final_v1.csv`
- A 실험, 5 fold × 5 seed = **25회**. **학습량 전부 동등** (600 iteration, 데이터 통과 3.17회)
- Δ·승/패·p 는 **`CoST (no scale/shift)` 기준**, 같은 fold×seed 로 짝지은 Wilcoxon signed-rank
- 모듈의 정의·수식·코드는 `proposed_final_v1_module_desciption.md`

## 3. 행별 해석

### 3.1 CoST → CoST (no scale/shift) : **−0.0116 → 기준**

원본 증강에서 `scale`·`shift` 를 제거한 것이 기준점이다. 거꾸로 읽으면 **증강을 되살리면
F1 이 0.0116 떨어진다** (1/24, p<.0001).

| | 변화 |
|---|---|
| 오염률 | .0054 → **.0026** (절반) |
| Rec(ns) | .9376 → **.9657** |
| 진입 MAE | 5.75 → **5.10 s**, bias −3.23 → −2.40 s |

**의미** — `shift` 가 "설정값에서 얼마나 떨어져 있나" 를 지우고 있었다. $e$ 는 이미 설정값을 뺀
오차라서 그 크기 자체가 상태를 가르는 물리량이다. **속도별로 보면 저속에서만 듣는다**
(V=50 AUROC +0.0707, V≥100 은 ±0.005) — 저속에서는 창 144 가 롤러 1회전뿐이라 요동으로는
가를 수 없고 오프셋으로만 가를 수 있기 때문이다.

### 3.2 + trunk separation : **+0.0018, p=0.134 → 무효**

trunk 를 둘로 나눴지만 **차수가 없으면 아무 일도 일어나지 않는다.**

**의미** — 원본 Hz `sfd` 는 추세 분리기와 **같은 시간축**을 쓴다. 그래서 공유 trunk 가
`L_MoCo`(시간축)에 맞춰져 있어도 Hz 분리기는 그 특질을 그대로 받아 쓸 수 있고, 분리할 이유가 없다.
**분리는 ③과 짝으로만 의미가 있다.**

### 3.3 + order tracking : **+0.0124, p=0.0056 → 단독으로 유효**

**세 요소 중 유일하게 단독으로 유의하다.**

| | 변화 | 읽는 법 |
|---|---|---|
| Prec(ns) | .8773 → **.9073** (+0.030) | 과도구간이라고 지목한 것이 실제로 과도구간인 비율이 올랐다 |
| 보존률 | .9903 → **.9936** (**25/25 전부 개선**) | 쓸 수 있는 정상 데이터를 더 많이 지켰다 |
| AUPRC(ns) | .8525 → **.8717** | |
| F1 표준편차 | .0989 → **.0851** | **fold 간 흔들림이 줄었다** |
| AUROC | .9782 → .9743 (−0.0039, n.s.) | 순위 자체는 못 올렸다 |
| 진입 MAE | 5.10 → **5.94 s** (악화), bias −2.40 → **−4.06 s** | **더 이르게** 판정한다 |

**의미** — 롤러 외란을 속도 무관한 차수 축에 고정하니 seasonal 표현의 변별력이 올라가
**판정(precision)과 보존이 개선**된다. 그런데 **진입 타이밍은 나빠진다** — 과도구간 종료를
더 이르게 본다. Prec(ns)↑ 와 진입 −4.06 s 가 함께 나오는 것은, 과도구간을 **짧게** 보되
그 안에서는 정확해졌다는 뜻이다.

**가장 약한 속도에서 가장 크게 듣는다**:

| $V$ | 50 | 75 | 100 | **125** | 150 | 175 | 200 |
|---|---|---|---|---|---|---|---|
| baseline F1(ns) | .9417 | .9868 | .9755 | **.9052** | .9269 | .9542 | .9693 |
| 차수의 F1 변화 | +0.0114 | +0.0018 | +0.0178 | **+0.0345** | +0.0188 | +0.0044 | **−0.0076** |

$V=200$ 만 손해다 — order window 의 시간 범위가 속도에 반비례해(15.7 s → 3.9 s) 고속에서는
과도구간의 29% 만 덮는 것이 후보 설명이다.

### 3.4 + trunk separation + freeze : **+0.0001, p=1.000 → 무효. 그런데 지표별로는 1위가 있다**

**차수가 없으면 분리 + 동결도 baseline 과 같다.** F1 기준으로는 완전히 무효다 (13/12).

그런데 지표를 나눠 보면 **이 조합이 네 지표에서 전체 1위**다.

| 지표 | 이 조합 | 전체 1위인가 |
|---|---|---|
| **오염률** | **.0013** | ✔ 전체 최저 (baseline .0026 의 절반) |
| **Rec(ns)** | **.9804** | ✔ 전체 최고 |
| **AUROC** | **.9848** | ✔ **전체 최고** (final v1 .9807 보다 높다) |
| **진입 MAE / bias** | **4.66 s / −1.55 s** | ✔ 전체 최고 |
| Prec(ns) | .8647 | ✘ dual 변형 중 최저 |
| 보존률 | .9887 | ✘ 전체 최저 |

**의미** — 순위(AUROC)·재현율·진입 타이밍은 가장 좋은데 **Prec(ns)가 낮아 F1 이 평평해진다.**
과도구간을 **넓게** 잡는 쪽으로 움직여서, 과도구간을 놓치지 않지만(Rec↑, 오염률↓) 정상 구간을
과도로 오판하는 양이 늘었다(Prec↓, 보존률↓).

> **공정 운영 관점에서는 이 조합이 더 맞는 경우가 있다.** 오염률이 최저(.0013)이고 진입 판정이
> 가장 정확하다(4.66 s) — "정상이라고 쓴 데이터가 오염되면 안 된다" 가 더 중요한 라인에서는
> 보존률 0.4%p 를 내주고 오염률을 절반으로 줄이는 쪽이 유리하다.
> **지표마다 최적 구성이 다르다**는 것을 논문에 적을 수 있다.

### 3.5 + trunk separation + order tracking : **+0.0153, p=0.0001**

**차수가 있을 때 분리가 작동한다.** 3.2 와 비교하면 같은 "분리" 인데 결과가 반대다.

| 비교 | 조건 | 분리의 효과 |
|---|---|---|
| 3.5 − 3.3 | 차수 **있음** | **+0.0029** (18/7) p=.006 ✔ |
| 3.2 − 기준 | 차수 **없음** | +0.0018 (16/9) p=.13 ✘ |

AUROC 도 함께 회복된다 — `order` 단독은 .9743(기준보다 낮음)인데 분리를 더하면 .9775 로 올라온다
(+0.0032, 20/5, p=.001). **차수가 못 올리던 지표를 분리가 되돌린다.**

**의미** — 차수 분리기는 trunk 출력을 **각도축으로 재표본화**해서 쓴다. 공유 trunk 는 거의
전적으로 `L_MoCo`(시간축)가 만들므로, **시간축 전용으로 변형된 특질을 다른 축으로 비트는 것**이
충돌이다. 전용 trunk 를 주면 그 변형을 피한다.

> **용량 때문이 아니다** — 공유 trunk 를 폭 2배(trunk 파라미터 1.99배)로 키우면 F1 −0.0018
> (**p=0.49**, 무효)이고, 차수 없는 쪽도 −0.0010 (p=0.77). 같은 용량에서 분리가 공유를 이긴다
> (**+0.0047, 20/5, p=0.0002**).
>
> **gradient 간섭 때문도 아니다** — seasonal 손실이 trunk 로 가는 gradient 를 완전히 차단해도
> (단위 검증 7.05 → 0.000000) 결과가 안 바뀐다 (**p=0.88**). 문제는 gradient 의 방향이 아니라
> **trunk 가 어디로 최적화되는가**다.

### 3.6 Proposed method (세 요소 전부) : **+0.0171, 22/3, p<0.0001**

| | 3.5 (동결 없음) → **final v1** |
|---|---|
| F1(ns) | .9285 → **.9303** (+0.0018, 18/7, p=.011) |
| AUPRC(ns) | .8769 → **.8802** (+0.0033, 19/6, p=.007) |
| AUROC | .9775 → **.9807** (+0.0032, **24/1**, **p<.0001**) |
| 보존률 | .9935 → .9932 (−0.0003, **0/22**, p<.0001) |
| 진입 MAE | 5.73 → **5.41 s** |
| **gradient 를 받는 파라미터** | 15.31 M → **13.69 M** |

**예측은 "얼려도 같을 것" 이었는데 유의하게 더 좋다.** 분리된 seasonal trunk 의 데이터 기인
이동량이 0.00022(trend trunk 의 1/10)였으므로 동결이 무해할 것으로 봤는데, **학습시키는 것이
오히려 해로웠다.**

**의미** — 주기 외란은 **학습해서 알아내야 하는 패턴이 아니다.** 롤러 둘레 $C$ 와 속도 $V$ 로
"차수 1 에 나타난다" 가 이미 결정되어 있고, 차수 재표본화가 그것을 결정론적으로 그 자리에 놓는다.
남은 일은 그 자리의 에너지를 재는 것뿐이라 **고정된 무작위 투영으로 충분하다.**
$\alpha = 0.0005$ 로 매우 약하게 눌린 seasonal 손실로 학습시키면 trunk 를 조금씩 끌어당겨
**어설픈 중간 상태**가 된다 — 무작위도 아니고 제대로 최적화된 것도 아닌 상태다.

**부수 효과 — 1위가 가장 적게 배운다.**

| 변형 | gradient 를 받는 파라미터 | baseline 대비 |
|---|---|---|
| baseline | 17,443,808 | — |
| `order` (공유) | 14,670,368 | −16% |
| `dual` (분리, 학습) | 15,307,616 | −12% |
| **final v1** | **13,694,528** | **−21%** |

**학습 용량을 21% 줄이면서 성능이 가장 좋다** — "파라미터를 늘려서 좋아진 것" 이라는 반론이
이 변형에서는 원천적으로 성립하지 않는다. 현장 배포 시 학습 비용도 작고, 롤러를 교체하면
$C$ 만 바꾸면 되어 **재학습이 필요 없다.**

유일한 역방향 신호는 보존률 −0.0003 으로, 크기는 무시할 수준이지만 **0/22 (동점 제외 전부 악화)**
라 방향이 체계적이다 — 논문 표에 함께 적는다.

## 4. 종합 — 세 요소의 관계

### 4.1 상호작용: 차수가 나머지 둘을 작동시킨다

| 조합 | ΔF1 | p | 읽는 법 |
|---|---|---|---|
| 분리만 | +0.0018 | .13 | 무효 |
| 분리 + 동결 | +0.0001 | **1.00** | 무효 |
| **차수만** | **+0.0124** | **.006** | **단독으로 유효** |
| 차수 + 분리 | +0.0153 | .0001 | 분리가 차수 위에서 작동 |
| **차수 + 분리 + 동결** | **+0.0171** | **<.0001** | 동결이 그 위에 더함 |

$$\text{차수}\;(+0.0124) \;\xrightarrow{\;+\text{분리}\;} +0.0153 \;\xrightarrow{\;+\text{동결}\;} +0.0171$$

**차수 추적이 전제이고, 분리와 동결은 그 위에서만 기여한다.** 차수 없이 분리·동결만 하면
baseline 과 구분되지 않는다 (p=0.13, p=1.00). 세 요소가 모두 필요하다.

### 4.2 지표별로 최적 구성이 다르다

| 지표 | 1위 구성 | 값 |
|---|---|---|
| **F1(ns)** · **AUPRC(ns)** | **Proposed (세 요소 전부)** | .9303 / .8802 |
| **AUROC** | 분리 + 동결 (차수 없음) | .9848 |
| **오염률** | 분리 + 동결 (차수 없음) | .0013 |
| **Rec(ns)** | 분리 + 동결 (차수 없음) | .9804 |
| **진입 MAE** | 분리 + 동결 (차수 없음) | 4.66 s |
| **보존률** · **Prec(ns)** | 차수만 | .9936 / .9073 |

**F1·AUPRC 를 주 지표로 쓰면 세 요소 전부가 최선**이다. 다만 운영 목표가 "오염 최소화" 나
"진입 시점 정확도" 라면 다른 구성이 유리하다 — 논문에서 이 trade-off 를 밝히는 것이 정직하다.

### 4.3 반증된 가설 — 함께 기록할 것

ablation 과정에서 네 가지 가설이 측정으로 뒤집혔다. 상세는
`idea/proposed_ideas_already_implemented.md` 의 "전체 결과 요약" 에 있다.

| 가설 | 반증 |
|---|---|
| 창을 분기별로 나누면 시간–주파수 상충이 해소된다 | **−0.0332** (4/21). seasonal 도 시점별 기술자라 긴 창이 경계를 흐린다 |
| 공유 backbone 이 **일반적으로** 해롭다 | 차수 없는 분리 **p=0.13**. 차수가 있을 때만 해롭다 |
| 두 손실의 **gradient 간섭**이 원인이다 | stop-gradient **p=0.88**. 간섭을 완전히 차단해도 변화 없음 |
| 보조 과제를 잘 풀면(`aux_r2`↑) 성능이 오른다 | `aux_r2` 올랐는데 F1 −0.131 (25/25 악화) |

> 뒤의 두 개는 **"측정한 양이 성능을 예측하지 못했다"** 는 같은 종류의 실패다 —
> 가중치 이동량과 `aux_r2`. 둘 다 그럴듯했지만 개입으로 확인하니 무관했다.
> **상관을 메커니즘으로 읽지 말 것.**
